## 本篇要回答的问题

1. 约定 A 下，`tokens`、`inputs`、`logits`、`labels` 各是什么形状？
2. 为什么 `[batch, 时间, 词表]` 不能原样送进 `CrossEntropyLoss`？
3. 填充和 SFT 的提示词，分别从哪一个下标开始不进损失？
4. 错一位的损失为什么会比正确的下一 token 损失低，而且仍然能下降？
5. 一次实验至少要记下哪些字段，种子才能说明什么？

## 这一步在做什么

一条因果语言模型的更新，数据流是：

```text
token id
  → inputs = tokens[:-1]
  → 模型 → logits，形状 [B, T-1, V]
  → labels = tokens[1:]
  → 去掉填充和不训练的位置
  → 对其余位置求平均负对数似然
  → 反向传播
  → 若梯度范数超过上限，按比例缩小
  → 优化器更新
  → 记录损失、进损失的 token 数、梯度范数、学习率
```

模型内部可以是任意可微网络。这一篇不依赖你已经实现注意力。它依赖标签比输入超前一位。

## 形状

一批里有 `B` 条序列，约定 A 之后的长度是 `T-1`，词表大小 `V`。

| 张量 | 形状 | 含义 |
| --- | --- | --- |
| `tokens` | `[B, T]` | 含填充的原始 id |
| `inputs` | `[B, T-1]` | 送进模型的前缀 |
| `logits` | `[B, T-1, V]` | 每个位置对词表的打分 |
| `labels` | `[B, T-1]` | 下一个 token；忽略的位置另作标记 |

PyTorch 的 `CrossEntropyLoss` 要求类别维在第 1 维：输入 `(N, C)` 或 `(N, C, …)`，目标是类别下标。语言模型习惯把 logits 放成 `[B, T-1, V]`，最后一维才是词表。原样传入时，库会把 `T-1` 当成类别数。

标准做法是收成两维再计算：

```text
logits.reshape(B * (T - 1), V)
labels.reshape(B * (T - 1))
```

被忽略的标签使用 `ignore_index`。当前稳定版文档里的默认值是 `-100`。文档把「对未被忽略的目标取平均」写在 `size_average=True` 下面，这就是默认的 `reduction="mean"`。自己实现平均时，若把忽略位置的损失写成 0 仍除以 `B * (T-1)`，填充会把损失稀释。那是另一个损失。换 PyTorch 版本时核对这一句。实验记录里写明分母是什么。

右填充配合因果掩码时，预测真实 token 的那些位置往往看不到右侧的填充，因为填充在它们的右边。左填充则不同：内容 token 的左边就是填充，因果掩码不会挡住左边。生成服务里常见左填充。填充位置的注意力掩码要单独做，不能靠「因果掩码大概够用」。

## 哪些标签参与损失

教学代码里用 `None` 表示忽略，落到 PyTorch 时换成 `-100`。

```python
def sft_labels(tokens: list[int], prompt_len: int, pad_id: int) -> list[int | None]:
    """约定 A。提示词内部的预测目标和填充都不计损失。"""
    labels: list[int | None] = []
    for offset, token in enumerate(tokens[1:]):
        target_index = offset + 1
        if token == pad_id or target_index < prompt_len:
            labels.append(None)
        else:
            labels.append(token)
    return labels
```

例：`tokens = [1, 8, 9, 2, 0, 0]`，`1` 是开始符，`8` 是提示，`9` 是回答，`2` 是结束符，`0` 是填充，`prompt_len = 2`。标签为

```text
[None, 9, 2, None, None]
```

对应关系：

| 输入位置看见的 token | 预测目标 | 是否计损失 |
| --- | --- | --- |
| 1（开始） | 8（提示） | 否，目标仍在提示里 |
| 8（提示） | 9（回答） | 是 |
| 9（回答） | 2（结束） | 是 |
| 2（结束） | 0（填充） | 否 |
| 0（填充） | 0（填充） | 否 |

模型仍然以提示为条件，因为输入里看得见 `1` 和 `8`。损失不要求它去「预测提示词本身」。结束符保留，模型才能学到停止。

预训练时没有提示掩码，`prompt_len` 可以看成 0，只忽略填充。SFT 才把提示对应的目标标成忽略。两种运行的损失数值不能直接比大小，因为分母里的 token 种类不同。记录里写上掩码规则。

## 错一位时损失会更好看

构造一个词表大小为 8 的分布，用来隔离「标签对齐」这一件事。序列 `tokens = [1, 5, 7, 0]`，`0` 是填充。每个位置的分布把概率 0.7 放在当前 token 上，把 0.1 放在下一个 token 上，其余 0.2 平分给其他类。

错误实现用位置 `t` 的分布去拟合 `tokens[t]` 自己，并且跳过填充。三个非填充位置的概率都是 0.7，平均 NLL 是 `-ln 0.7 ≈ 0.3567`。

正确实现用位置 `t` 预测 `tokens[t + 1]`，填充目标不计入。参与的是预测 5 和预测 7 的两步，概率都是 0.1，平均 NLL 是 `-ln 0.1 ≈ 2.3026`。

错误损失更低。若模型真的把概率堆在「抄写当前输入」上，这个错误目标还会继续下降。自动微分会忠实地优化你写下来的损失。检查方法是单元测试：手写一条短序列和一组概率，断言 NLL 等于下一 token 的值，而不是当前 token 的值。脚本 `check_training_step` 断言这两个数。

再多记两个同类错误。

- 双重错位：切分时用了约定 A，损失内部又把标签左移一次。预测目标变成了下下个 token。
- SFT 把提示词也算进损失。模型把容量花在抄写提示上，回答部分的 token 在平均里被稀释。训练损失可以看起来更好。

## 梯度裁剪与日志

设梯度向量的范数是 `‖g‖`，上限是 `c`。若 `‖g‖ > c`，把梯度换成 `g * c / ‖g‖`。方向不变，长度变成 `c`。它限制一步的大小。损失设错时，裁剪仍然优化那个错误损失。

一次迭代至少记录：

| 字段 | 用来发现什么 |
| --- | --- |
| 步数 | 曲线的横轴 |
| 损失 | 是否下降、是否变成 NaN |
| 参与损失的 token 数 | 分母变了没有 |
| 梯度范数 | 是否爆炸；裁剪之前的范数才有警报意义 |
| 学习率 | 和调度器是否一致 |
| 数据版本或数据指纹 | 这次曲线对应哪一版数据 |
| 代码版本 | 哪一次提交 |
| 种子 | 你实际固定了哪几个随机源 |
| 掩码规则 | 预训练、SFT 或自定义忽略 |

tokens per second 是系统吞吐，不是质量。验证集上的任务指标另记，不要只记训练损失。

种子固定的是你控制得了的随机源：Python、NumPy、以及框架在 CPU 上的生成器，还有数据顺序。GPU 上逐比特复现常常做不到。PyTorch 的随机性说明写了哪些操作是不确定的。记录环境和种子，比把「完全可复现」写成没有条件的句子更准确。

## 这一步的外面是数据并行

单机上的这一步，在数据并行里被复制到每个 worker。每个 worker 持有完整模型，读取不同的小批量，得到一份梯度。同步时对梯度求和再除以 worker 数，使更新对应平均梯度。有效批量是各 worker 样本数之和。

批量变大之后，学习率要不要线性放大，取决于优化器和实践，不是数据并行的定义的一部分。用损失和验证指标核对，不把某篇论文的批量公式直接当成当前运行的事实。

张量并行、流水线并行和 ZeRO 切的是别的资源，定义在阶段说明里。

## 容易算错的地方

- `logits` 的词表维在最后，`CrossEntropyLoss` 的类别维在第 1 维。中间用 `reshape` 而不是想当然地 `permute`，除非你有测试覆盖这两种形状。
- 忽略位置若只把损失置零、分母仍用满长度，填充比例会直接改变你看到的损失。
- 右填充上的因果掩码，不能推出左填充也安全。
- 梯度范数在裁剪之后再记录，曲线会被顶在 `c`，失去警报。
- 训练损失下降只说明当前这个损失在下降。错一位的例子里，更低的数对应更差的目标。

## 练习

### 练习 1：写形状

- 目标：四个张量的形状一次写对。
- 限制：不看正文的表，写完再对照。
- 题面：`B = 2`，`T = 4`，`V = 100`，使用约定 A。`inputs`、`logits`、`labels` 的形状是什么？送进 `CrossEntropyLoss` 的 logits 形状是什么？
- 完成标准：`[2, 3]`、`[2, 3, 100]`、`[2, 3]`，以及 `[6, 100]`。

<details>
<summary>参考解答</summary>

约定 A 把时间从 4 变成 3。类别维收成二维时，`2 * 3 = 6` 行，100 列。

</details>

### 练习 2：读懂好看的错误损失

- 目标：把 NLL 和标签对齐连起来。
- 限制：可以先算 `-ln 0.7` 和 `-ln 0.1`，再看脚本。
- 题面：按正文的分布，错误的「预测当前 token」平均 NLL 是多少？正确的下一 token 平均 NLL 是多少？为什么错误的数更小不能说明实现更好？
- 完成标准：约 0.3567 和约 2.3026，并指出错误目标在抄写当前输入。

<details>
<summary>参考解答</summary>

`-ln 0.7 ≈ 0.3567`，`-ln 0.1 ≈ 2.3026`。错误实现把 0.7 的概率当成命中，正确实现命中的是 0.1 的那一项。脚本 `check_training_step` 复核。损失更低只说明更贴近它所优化的目标。

</details>

### 练习 3：SFT 标签

- 目标：提示词作为条件，而不作为目标。
- 限制：纸笔。
- 题面：用正文的 `sft_labels`，`tokens = [1, 8, 9, 2, 0, 0]`，`prompt_len = 2`，`pad_id = 0`。写出标签。若 `prompt_len = 0`，标签变成什么？
- 完成标准：第一问是 `[None, 9, 2, None, None]`。第二问只忽略填充。

<details>
<summary>参考解答</summary>

`prompt_len = 0` 时，目标下标都不会因为提示被丢掉，标签是 `[8, 9, 2, None, None]`。脚本只断言了 `prompt_len = 2` 的那一组。

</details>

### 练习 4：左填充

- 目标：因果掩码挡住的是右边。
- 限制：画五个位置即可。
- 题面：序列内容是 `c₀ c₁ c₂`，左填充后模型看见 `pad pad c₀ c₁ c₂`。预测 `c₁` 时，因果掩码允许看见哪些位置？其中有没有填充？
- 完成标准：指出预测 `c₁` 的那个输入位置看得见左边两个填充。

<details>
<summary>参考解答</summary>

设位置 0、1 是填充，位置 2 是 `c₀`，位置 3 是 `c₁`。约定 A 下，预测 `c₁` 的输入位置是位置 2，因果掩码允许它看见 0、1、2，其中 0 和 1 是填充。需要填充掩码把这两个 key 去掉。右填充时，同样的内容 token 位于左端，它们的未来才是填充，因果掩码已经把未来挡住。

</details>

### 练习 5：裁剪不改正损失

- 目标：分开「步长」和「目标」。
- 限制：纸笔。
- 题面：梯度 `g` 的范数是 10，上限 `c = 2`。裁剪后的向量是什么？若损失用了错一位的标签，裁剪会不会把目标改回下一 token？
- 完成标准：裁剪后是 `0.2 g`。第二问的回答是不会。

<details>
<summary>参考解答</summary>

`g * 2 / 10 = 0.2 g`。裁剪只改长度。反向传播的目标仍是程序里写的那个损失。

</details>

### 练习 6：一次可以讨论的实验记录

- 目标：字段足够让别人发现掩码和数据版本，而不是一句「已固定种子」。
- 限制：按你设想的一次 SFT 填写，不要编造没有跑过的指标曲线。
- 题面：列出你会记录的字段。种子那一行写明你准备固定哪些随机源，以及你不声称哪一种复现。
- 完成标准：包含数据版本、掩码规则、参与损失的 token 定义、梯度范数是裁剪前还是裁剪后。

<details>
<summary>参考解答</summary>

合格记录至少有：代码版本、数据指纹、SFT 掩码（提示不计损失、填充不计损失）、分母是有效 token 而不是 `B*T`、学习率、有效批量、裁剪上限、裁剪前梯度范数、验证指标的名字。种子行写 Python、NumPy 和框架的 CPU 生成器。GPU 上不声称逐比特相同，并引用随机性文档作为依据，而不是作为已经完成的实验。

</details>
