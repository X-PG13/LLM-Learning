## Prefill 与 decode

自回归生成有两段前向。提示已经给定，长度记为 `P`。模型要接着写出新 token。

**Prefill。** 一次前向吃进整段提示。每个位置都算自己的 query、key、value，因果掩码仍是「位置 `i` 只看见 `j ≤ i`」。这一次结束时，提示里每个位置的 key 和 value 都已经可以留下。用来采样的是**最后一个提示位置**的 logits：它的条件是整段提示，预测的是第一个新 token。

**Decode。** 第一个新 token 已经选定。下一步只把这一个 token 送进模型，算出它自己的 query、key、value，key 和 value 追加进缓存，query 和缓存里所有 key 做注意力，再采样下一个 token。生成长度 `N`（含第一个新 token）时，prefill 产出第 1 个，decode 再走 `N - 1` 步。

两边的矩阵乘看见的 token 数不同。Prefill 的线性层同时处理一批里所有提示位置。Decode 的线性层在每步只处理本步新进来的那一个位置。批量把多条请求拼在一起时，这个行数等于批里的请求数。上下文长度出现在注意力要读的缓存里。

[训练一步](01-训练一步的数据流.md) 里的左填充在这里仍然有效：一个 prefill 批量里各条提示长短不同、左边补了填充时，因果掩码挡的是右边，挡不住左边的填充。填充位置要单独掩掉。

## 缓存与重算

因果掩码已经保证：位置 `i` 的输出不依赖 `i` 之后的 token。因此旧位置的 key、value 不会因为后面多了一个 token 而改变。新位置需要的是自己的 query，以及从开头到自己的 key 和 value。这些 key、value 若在当初那个位置第一次出现时就算好并留下，精确算术下和新把整段再乘一遍得到的是同一组向量。注意力输出也就相同。省下的是对历史位置重复做投影和分数；付出去的是把这些向量存在显存里。

用一个 `d_k = 1` 的头看这个等式。缩放因子是 `sqrt(1) = 1`。位置 0 已经留下 `k = 1`、`v = 4`。新位置的 `q = 1`，`k = 1`，`v = 0`。

```text
分数 = (q·k₀, q·k₁) = (1, 1)
softmax = (1/2, 1/2)
输出 = (1/2)·4 + (1/2)·0 = 2
```

把两个位置放进同一次前向，新位置看见的 key、value 还是这两个数，输出还是 2。若实现漏掉缓存里的 `k₀`，分数只剩 `(1)`，输出变成 0。那是少读了一个 key，和「缓存是近似」不是同一件事。

位置 0 的输出在它自己那一步是 `v = 4`。新 token 到来之后，因果掩码仍不让位置 0 看见新的 key，所以这个输出不必重写。

以上是实数运算、加法可以随便交换的情形。浮点把加法顺序换了，末位可以差一个舍入。比较「开缓存」和「整段重算」时，要允许这一层舍入，而不是要求每个比特相同。

## 显存账

每个留下的位置、每一层，要存 key 和 value 两份。每份的宽度是 KV 头数乘头维。批量里每条序列各有一份。元素占的字节数记为 `b`。

```text
字节数 = 层数 × 2 × KV头数 × 头维 × 分配的位置数 × 批量 × b
```

这里的 2 是 key 和 value。头数是 **KV 头数**，不是 query 头数。三种注意力在这张账上只差这一个因子：

| 做法 | KV 头数 | 相对 GQA 的缓存 |
| --- | --- | --- |
| MHA | 等于 query 头数 | 按 query 头 / KV 头 放大 |
| GQA | 小于 query 头数，且能整除 | 1 |
| MQA | 1 | 按 KV 头数缩小 |

Mistral 7B 论文表 1 给出一组 7B 量级的 GQA 形状：32 层，query 头 32，KV 头 8，头维 128。同一张表的滑动窗口 `W = 4096` 配有滚动缓冲：分配长度就是 `W`，位置 `i` 的 key、value 写在 `i mod W`。前缀短于 `W` 时，缓冲后段还空着，分配长度已经是 `W`。前缀长于 `W` 时，新位置覆写旧槽，分配长度也不再增加。信息可以逐层向前传，理论感受野因此长于 `W`；缓存字节数跟着分配的 `W`，不跟着感受野。

公式本身只认「实际分配的位置数」。下面先算一种随写入增长的分配：已经写入 2048 个位置，批量 4，`b = 2`（fp16 和 bf16 都是这个宽度）。

```text
32 × 2 × 8 × 128 × 2048 × 4 × 2
```

全部写成 2 的幂：`32 = 2^5`，key/value 的 2 与字节数 2 合起来是 `2^2`，`8 = 2^3`，`128 = 2^7`，`2048 = 2^11`，`4 = 2^2`。指数相加：

```text
5 + 2 + 3 + 7 + 11 + 2 = 30
```

字节数是 `2^30 = 1073741824`。按 1024 进位，这是 1 GiB。十进制的 `10^9` 字节比它少，两套单位不要混用。

同一形状把 KV 头数换成 query 头数 32，就是 MHA，缓存变为 4 倍，`2^32 = 4294967296` 字节，即 4 GiB。换成 MQA 的 1 个 KV 头，缓存变为 1/8，`2^27 = 134217728` 字节，即 128 MiB。GQA 缩小的是 KV 这一维。query 头数仍是 32，query 侧投影按 32 个头计。那部分参数差属于结构主题，不在这张显存账里展开。

表 1 的滚动缓冲按 `W = 4096` 分配。批量 4、`b = 2` 时，前缀 2048 和前缀 8192 的分配字节数相同，都是上面的 2 倍，`2^31` 字节，即 2 GiB。前缀 8192 不会把已经覆写的前一半再存一份。只有分配随写入增长、并且前缀仍短于窗口，才回到 2048 那个 `2^30`。

权重占用不随序列变长。缓存会。两边谁更大，用实际参数量和实际分配的长度乘出来再比。模型名字里的「7B」是量级，表 1 没有给出总参数个数。

## Decode 为什么吃带宽

一次矩阵乘的算术强度，这里定义成：浮点次数除以这一步必须从内存搬进来的字节。Williams、Waterman、Patterson 的 roofline 把经过缓存过滤之后、真正打到 DRAM 的比值叫 operational intensity，可达速度是下面两者中较小的那个：

```text
可达速度 = min(峰值浮点速度, 内存带宽 × 运算强度)
```

两条线的交点叫脊点，横坐标是 `峰值 / 带宽`。强度低于脊点时，上限由带宽决定；高于脊点时，上限由峰值浮点决定。缓存若真能装下权重复用，实际打到 DRAM 的字节会少一些，强度会高一些。Decode 时权重通常远大于片上缓存，粗估就把权重和 KV 都算进必须搬运的字节。

记号沿用 [记号约定](../记号约定.md)：`y = x @ W.T`，`W` 的形状是 `(d_out, d_in)`。一次乘加计 2 次浮点运算。`x` 有 `S` 行时，浮点次数是 `2 S d_out d_in`。fp16 或 bf16 下，权重占 `2 d_out d_in` 字节，读 `x` 与写 `y` 各占 `2 S d_in` 或 `2 S d_out` 字节。方阵 `d_in = d_out = d` 时：

```text
强度 = (2 S d²) / (2 d² + 4 S d) = (S d) / (d + 2 S)
```

忽略激活、只算权重时，fp16 的强度趋于 `S`。`S = 1` 时趋于 1 次浮点每字节：每个权重被一个 token 用一次，乘加两次，权重本身两个字节。

取 `d = 4096`。Decode 一步、批量 1，相当于 `S = 1`：

```text
强度 = 4096 / (4096 + 2) = 2048/2049
```

激活相对权重只有 `2S/d = 1/2048`，所以它只比 1 略小。Prefill 把 2048 个位置一起算，`S = 2048`：

```text
强度 = (2048 × 4096) / (4096 + 2×2048) = 2048×4096 / 8192 = 1024
```

教学用的机器：峰值 `10^14` 次浮点每秒，带宽 `2×10^12` 字节每秒。这两个数是用来摆脊点的，不是某一张卡的标称。脊点是

```text
10^14 / 2×10^12 = 50
```

次浮点每字节。`2048/2049` 远低于 50，这一步的上限是带宽：忽略激活时可达 `2×10^12` 次浮点每秒，是峰值的 `1/50`。把激活算进去，比例是 `2048 / (50 × 2049)`，比 `1/50` 还略小。Prefill 的 1024 高于 50，同一次方阵乘翻到计算一侧。Decode 慢，是因为每个新 token 都要把整份权重搬进来，却只用它做很少的乘加；Prefill 让同一份权重服务很多位置，搬运才摊得薄。

批量把多条请求的 decode 拼进同一次矩阵乘，`S` 换成批里的新 token 数。忽略激活时，fp16 的强度等于这个批量，所以批量要到 50 才碰到这台教学机器的脊点。把激活算回去，批量 8、`d = 4096`：

```text
强度 = (8 × 4096) / (4096 + 16) = 2048/257
```

`2048/257` 仍低于 50。加大批量是把同一份权重多用几次。真正的卡用它自己的峰值和带宽重新算脊点，50 只属于这台教学机器。

注意力在 decode 时还要读缓存。一层、一条序列、长度 `S`，只计 K 和 V 的读、不计分数：浮点次数按每个 query 头对 `S` 个 key 做两次长度为头维的乘加，共 `4 × query头 × S × 头维`。fp16 的 KV 字节是 `4 × KV头 × S × 头维`。`S` 和头维约掉之后，强度等于 `query头 / KV头`。表 1 的形状是 `32/8 = 4`，仍远低于脊点 50。分数向量的字节数大约是 KV 的 `query头 / (2 × KV头 × 头维) = 1/64`，粗估略去它，强度的量级不变。

`d = 4096` 的一层 fp16 方阵权重是 `2 × 4096² = 33554432` 字节。表 1 的一层 KV，在长度 2048、批量 1 时是 `2 × 8 × 128 × 2048 × 2 = 8388608` 字节。权重是这份 KV 的 4 倍，这一步的搬运大头仍是权重，强度靠近 1。上下文或批量再加大，KV 占的字节上升。注意力自己的强度仍是 `query头 / KV头`，权重那一部分仍靠近 1，两边都低于脊点 50。

## 静态批、迭代级调度、分页

生成长度事先不知道，短的会先结束。

**静态批。** 若干请求组成一批之后一直留到最长的那条结束。短请求在自己写完之后，槽还被占着。四条请求要生成的长度是 2、2、2、8：

```text
步 1–2：四条都在算
步 3–8：只剩最长的那条，另外三个槽空着
有用的 token 步 = 2+2+2+8 = 14
占用的槽步 = 4×8 = 32
14/32 = 7/16
```

空着的 18 个槽步是这批内部的等待，不是模型多算了别的分布。

**迭代级调度。** Orca 把调度从「整条请求」改成「每一次迭代」。一个迭代产出本批里每条仍在生成的请求的下一个 token。已经结束的请求在这个迭代之后离开，排队中的请求可以在下一个迭代进来。服务系统里常把这件事叫连续批处理（continuous batching）。它提高的是机器上的 token 吞吐：空槽能让给新请求。一条请求自己的条件分布不变，变的是谁和它同一批发车。

长度不同的请求塞进同一次前向时，线性层仍可沿批量维拼起来，每个位置的矩阵乘不看别的请求有多长。注意力要读的是本请求自己的缓存，长度各不相同。Orca 的选择批处理因此把注意力按请求分开算，线性层继续合并。后来的实现可以把变长注意力做成一个核，调度上的事实不变：每一轮都可以换人，注意力尊重每条序列自己的长度。

没有新请求在排队时，迭代级调度也不会凭空填满那些空槽。上面的 `7/16` 是「不准中途换人」的占用；允许换人之后，占用取决于队列里还有没有活。

**分页。** 早先的缓存管理常按最大长度预留一整段连续显存。请求实际很短时，这段里大部分位置从未写入，这是内部碎片；每条请求预留的长度不同，段与段之间还会留下放不进下一条的空隙，这是外部碎片。PagedAttention 把一条请求的 KV 切成固定大小的块，块里装固定个数 token 的 key 和 value。块与块在物理显存上不必相邻。一张块表把逻辑块号映射到物理块号，和操作系统里页表把虚拟页映射到物理页是同一类想法。请求结束，物理块回到空闲链表，下一条请求按块取用，不必把它和还在跑的请求紧挨着放。

块内没写满的最后一块仍是内部碎片。块越小，这份碎片越少，块表越长。vLLM 在这套分页上做服务调度。论文给出的是他们测量的系统里，预留式管理只用到已分配 KV 显存的一部分；「接近零浪费」是相对「按最大长度预留整段」而言，最后一块里的空位还在。

教学例子，不来自论文里的剖面。最大长度按 16 预留，三条请求实际留下 5、5、6 个位置，块大小 4。

```text
连续预留：3 × 16 = 48 个位置槽，真正写入 16 个，空着 32 个
分页：⌈5/4⌉ + ⌈5/4⌉ + ⌈6/4⌉ = 2+2+2 = 6 块，6×4 = 24 个位置槽
最后一块的内部碎片：(4−1) + (4−1) + (4−2) = 8
```

第三条结束时，它的 2 块可以回到空闲链表。新来一条要 7 个位置的请求需要 2 块，可以直接拿走，不必搬动另外两条的缓存。

分页不改注意力在精确算术下的结果。它改的是 KV 放在哪里、空位能不能还给别人。束搜索里多条假设共享同一段前缀时，块表也可以让这些假设指向同一批物理块；那是 PagedAttention 论文里的共享，不是本篇的手算。

## 解码策略对延迟的影响

贪心、温度、top-k、top-p 从同一组 logits 里取出一个 token。分布怎么变，在 [Token 与下一个词](../06-大语言模型/01-Token与下一个词.md)。系统上的共同点是：一次目标模型的前向承诺一个新 token。在词表上做一次抽样或一次 argmax，相对把整份权重读进来，通常是小头。

束宽 `K` 每步留下 `K` 条假设。线性层看见的批量大约是 `K` 乘请求数，缓存若每条假设各存一份，也大约是 `K` 倍。前缀相同的块可以共享，见上一节。延迟随 `K` 上升。束搜索选出的序列，和温度采样抽到的序列，不是同一个解码分布。

**投机解码**用一个便宜的草稿模型先写 `γ` 个 token，再用目标模型的一次前向同时检查这些位置。Leviathan、Kalman、Matias 的接受规则（speculative sampling）保证：被接受的前缀加上拒绝处按残差分布重抽的那个 token，整体的输出分布与「只用目标模型逐步抽样」相同。草稿模型自己的分布不必等于目标模型。被拒绝位置之后的草稿丢掉。每一轮目标模型除了接受若干草稿，总会再贡献一个 token：要么是拒绝处重抽的，要么是 `γ` 个草稿全部接受之后多算出来的下一个。

记 `β` 为给定前缀时，下一个草稿 token 被接受的概率，`α = E(β)`。论文在 `β` 独立同分布的假设下得到：一轮产出的 token 数是成功概率 `1−α`、封顶 `γ+1` 的截断几何随机变量，期望是

```text
(1 − α^(γ+1)) / (1 − α)
```

`α = 1` 时每一轮都接受全部草稿并再写出一个，期望是 `γ+1`，公式的分母为零，要单独算。`α = 0` 时期望是 1，这一轮只剩下目标模型自己的那个 token。

手算取 `α = 4/5`，`γ = 3`。这是为了分数能约干净，不是论文某次实验的测量。设 `X` 为被接受的草稿个数。

```text
P(X=0) = 1/5
P(X=1) = (4/5)·(1/5) = 4/25
P(X=2) = (16/25)·(1/5) = 16/125
P(X=3) = (4/5)^3 = 64/125
```

四项通分到 125：`25/125 + 20/125 + 16/125 + 64/125 = 1`。被接受草稿数的期望：

```text
0·(1/5) + 1·(4/25) + 2·(16/125) + 3·(64/125)
= 20/125 + 32/125 + 192/125
= 244/125
= 1.952
```

加上目标模型必然再给出的一个 token，一轮期望产出

```text
244/125 + 1 = 369/125 = 2.952
```

和公式一致：`1 − (4/5)^4 = 1 − 256/625 = 369/625`，再除以 `1/5`，得到 `369/125`。

墙钟上，论文把一轮的代价写成 `γ` 次草稿步加 1 次目标模型前向。设草稿一步的时间是目标模型 decode 一步的 `c` 倍，期望加速是

```text
(1 − α^(γ+1)) / ((1−α) (γ c + 1))
```

`c = 1/10` 时，分母的时间是 `3/10 + 1 = 13/10`，加速是

```text
(369/125) / (13/10) = 738/325 ≈ 2.2708
```

`c = 0` 时加速就是 `369/125` 本身。`γ` 很大且 `c = 0` 时，上界趋向 `1/(1−α) = 5`，本例的 2.952 还在这条上界下面。生成很短时，加速还会被「总共要生成的 token 数」封顶：目标模型每轮至少跑一次，轮数不会比 token 数更多。

被拒绝的草稿白算了，所以算术次数可以高于普通 decode。Decode 已经落在带宽一侧时，多出来的算术不一定变成墙钟：权重本来就要读，验证 `γ` 个位置是在同一次读权重时多做一些乘加。`γ` 大到验证前向本身变成一次不短的 prefill 时，`c` 和「验证等于一步 decode」都要重新量，不能再沿用这个分母。并行提出草稿的结构（一次前向写出多个草稿头）改的是代价模型，接受规则要另对论文。

## 权重量化

把权重收成更少的位数，搬权重的字节数就变少。Decode 被权重的带宽卡住时，这是直接对症的部分。激活也可以量化；本篇的手算只做权重。位数变了之后，下一步 token 的分布可能改变，任务指标要在量化后的模型上重测。四个数上的最大绝对误差回答不了「argmax 会不会换」。

**对称 int8。** 与 LLM.int8() 论文里的 absmax 一致：用最大绝对值把权重放进 `[-127, 127]`，0 的量化值是 0。

```text
s = max |w| / 127
q = clip(round(w / s), −127, 127)
ŵ = q · s
```

`round` 取最近整数；恰好落在两个整数正中时远离 0，于是 `0.5 → 1`，`−0.5 → −1`。本篇的例子没有正中的点，写出规则是为了和脚本用同一种舍入。最大绝对值是 0 时，权重全是 0，量化结果也是 0，不再除以这个最大值。

四个权重 `2/5, −6/5, 1/5, 4/5`（即 `0.4, −1.2, 0.2, 0.8`）。最大绝对值是 `6/5`，

```text
s = (6/5) / 127 = 6/635
```

`w/s` 等于 `127/3, −127, 127/6, 254/3`，最近整数是 `42, −127, 21, 85`。还原 `q·s`：

```text
42·6/635 = 252/635
−127·6/635 = −6/5
21·6/635 = 126/635
85·6/635 = 510/635
```

和原来的 `254/635, −762/635, 127/635, 508/635` 相减，误差是

```text
2/635, 0, 1/635, −2/635
```

最大绝对误差是 `2/635`。没有发生截断，因为最大值正好落到 `−127`。此时每个分量的绝对误差不超过半个步长 `s/2 = 3/635`，`2/635` 确实更小。

**对称 int4。** 本篇把整数范围取成 `[-7, 7]`，让 0 仍在正中。4 位本来有 16 个码，`[-7, 7]` 只用 15 个，空出一个码来换对称。同一组权重，`s = (6/5)/7 = 6/35`。`w/s` 等于 `7/3, −7, 7/6, 14/3`，最近整数是 `2, −7, 1, 5`。误差是

```text
2/35, 0, 1/35, −2/35
```

最大绝对误差是 `2/35`。步长从 `6/635` 变成 `6/35`，放大 `127/7` 倍；这组数在两套格子上的相对位置相同，最大绝对误差也放大 `127/7` 倍。半步长是 `3/35`，误差仍在半步之内。GPTQ 实验里的 4 位网格是非对称的 min-max，16 个码都用上，零点不一定在正中。上面这组 `[-7, 7]` 是本篇为了手算对称误差而取的约定。

**非对称。** 权重挤在 0 的一侧时，对称网格空着另一侧的码。LLM.int8() 的 zeropoint 把区间铺满 `[-127, 127]`，归一化动态范围是 `2·127 / (w_max − w_min)`。本篇取步长为这个数的倒数，整数跨度 254：

```text
s = (w_max − w_min) / 254
q = clip(round((w − w_min) / s) − 127, −127, 127)
ŵ = w_min + (q + 127) · s
```

区间关于 0 对称、并且舍入不落在两个整数正中时，这个格子和 absmax 重合。手算 `(0, 1, 5)`。`s = 5/254`。`(w − 0) / s` 等于 `0, 254/5, 254`，最近整数是 `0, 51, 254`，减去 127 得到 `q = (−127, −76, 127)`。还原：

```text
(q + 127) · 5/254 = (0, 255/254, 5)
```

中间那个权重的误差是 `1 − 255/254 = −1/254`。同一组数若用对称 absmax，最大绝对值是 5，`s = 5/127`，`1 / s = 127/5 = 25.4`，最近整数 25，还原 `125/127`，误差是 `2/127 = 4/254`。非对称把步长用在真正有数据的 `[0, 5]` 上，这一位的误差更小。全是正数时对称网格的负半轴没有对应的权重。

**按通道和按分组。** 一个缩放因子管的范围越小，一个离群权重越不容易把别人的步长撑大。按通道：权重矩阵每一行（一个输出通道）用自己的最大绝对值。按分组：一行内部每 `G` 个权重共用一个缩放因子。`G = 2` 时，上面四个数分成 `(2/5, −6/5)` 和 `(1/5, 4/5)`。前一组的最大值就是整个向量的最大值，缩放和误差与张量级对称 int8 相同。后一组最大绝对值是 `4/5`，`s = 4/635`：

```text
(1/5) / s = 127/4 = 31.75 → 32
(4/5) / s = 127
还原 32·4/635 = 128/635
误差 = 127/635 − 128/635 = −1/635
```

`4/5` 这个权原本在张量级网格上的误差是 `−2/635`，分组之后落到格子上，误差是 0。这一组的最大绝对误差从 `2/635` 降到 `1/635`。GPTQ 报告过组大小 128 和 1024：更小的组困惑度更好，每个组的缩放（和非对称时的零点）要额外存。128 是他们实验里的粒度，不是缩放公式的一部分。

缩放和最近舍入是上面这些手算。GPTQ 在此之上用近似二阶信息决定怎么舍入，让后面的权重吸收前面已经舍入的误差，并且仍然是一次量化、不再训练。只做最近舍入的基线，论文里放在同一套按行非对称 min-max 网格上，方便和 GPTQ 比。LLM.int8() 除了向量各自一个 absmax 缩放，还把少量绝对值很大的特征维留在 16 位矩阵乘里，其余仍走 8 位。他们的工作里，这个阈值取 6 就把性能损失压到接近零；换模型时离群维落在哪里要重新看。QLoRA 的 NF4 是另一套非均匀的 4 位码，本篇的均匀步长不包括它。

## 首 token 时间、每 token 延迟、吞吐

排队时间为 0 时，本篇把首 token 时间（TTFT）定义成：从请求开始被计算，到第一个新 token 产生。它包含 prefill，以及从最后一个提示位置取出那个 token。其后每个新 token 的时间记为每 token 延迟（TPOT），是 decode 步的平均间隔。生成 `N` 个新 token 的端到端时间是

```text
TTFT + (N − 1) × TPOT
```

手算：`TTFT = 200` 毫秒，`TPOT = 25` 毫秒，`N = 9`。

```text
200 + 8 × 25 = 400 毫秒
```

这条请求的输出吞吐是 `9 / 0.4 = 22.5` 个 token 每秒。分母是墙钟秒，分子是输出 token，不含提示。把提示也算进吞吐时要另写分子，两个数不能并排放。

服务吞吐是一段时间里完成的输出 token 除以这段墙钟，通常跨多条请求。它不能由 22.5 乘批量得到：批量改变每步要读的 KV、也改变这一步的时间。静态批里短请求提前结束后，槽还空着，机器的吞吐低于「四条都一直在写」的想象。迭代级调度和分页针对的是这种空位，不是把单请求的 TPOT 变小。一条请求自己的 TPOT 在大批量里可能变差，同时机器每秒写出的 token 变多。两个数一起记。

质量不在这三个数里。训练损失、任务对错和这里的延迟是两套记录，和 [训练一步](01-训练一步的数据流.md) 里「每秒 token 数是吞吐」是同一条界限。

## 容易算错的地方

- 字节公式里的头数写成 query 头 32。表 1 的例子会从 1 GiB 变成 4 GiB。
- 滚动窗口已经写满，仍用对话全长当分配长度。固定缓冲在前缀还短于 `W` 时，分配长度已经是 `W`。
- 把 `2^30` 字节说成 `10^9` 字节。
- Decode 的线性层强度用了上下文长度。上下文长度在 KV 的读里，线性层的行数是本步的新 token 数。
- 预留式管理里从未写入的长尾，和分页最后一块里的空位，当成同一种碎片。
- `α = 1` 仍去代 `(1−α^(γ+1))/(1−α)`。分母是 0，期望另行等于 `γ+1`。
- 投机解码只除目标模型的一步，漏掉 `γ c`。生成只有几个 token 时，仍用长生成的加速比。
- 对称缩放用了带符号的最大值。全正的权重会把负半轴空着。
- 正中舍入的方向没定。`0.5` 在「远离 0」和「向偶数」下会差 1。
- 端到端时间写成 `TTFT + N × TPOT`。第一个 token 算了两次，上例会得到 425 毫秒。
- 用单请求的 22.5 token/s 乘批量当作服务吞吐。
- 权重量化误差小，就认为任务分数不变。分布要在量化后的模型上重测。

## 练习

### 练习 1：把缓存乘完

- 目标：KV 头数、留下的长度、字节宽度各就各位。
- 限制：先把因子写成 2 的幂再相加指数。
- 题面：仍用表 1 的 32 层、8 个 KV 头、头维 128。只为已写入的 2048 个位置分配，批量 4，每元素 2 字节，字节数是多少？若误用 32 个 query 头，变成多少？滚动缓冲固定按窗口 4096 分配时，前缀 2048 和前缀 8192 各是多少字节？
- 完成标准：`2^30`、`2^32`，两种前缀都是 `2^31` 字节。

<details>
<summary>参考解答</summary>

指数 `5+2+3+7+11+2 = 30`。query 头是 KV 头的 4 倍，多一个 `2^2`，得到 `2^32`。固定窗口 4096 是 2048 的 2 倍，字节数是 `2^31`；前缀 8192 覆写旧槽，分配长度仍是 4096。脚本 `check_inference` 复核。

</details>

### 练习 2：脊点的两侧

- 目标：用强度和脊点决定上限来自带宽还是峰值。
- 限制：方阵 `d = 4096`，fp16，激活的读写都算进字节。
- 题面：批量 1 的 decode（`S = 1`）和长度 2048 的 prefill，强度各是多少？教学脊点 50 时，哪一侧被带宽卡住？忽略激活时，decode 的可达浮点速度是峰值的几分之几？
- 完成标准：`2048/2049` 与 1024；decode 在带宽一侧，这次 prefill 在计算一侧；`1/50`。

<details>
<summary>参考解答</summary>

`(S d)/(d+2S)` 在 `S = 1` 时是 `4096/4098 = 2048/2049`，在 `S = 2048` 时是 1024。1024 大于 50。忽略激活时强度为 1，可达速度是 `2×10^12`，占峰值 `10^14` 的 `1/50`。

</details>

### 练习 3：两种空位

- 目标：把「人不能中途下车」和「显存按最大长度预留」分开。
- 限制：纸笔。
- 题面：生成长度 2、2、2、8 的静态批，有用 token 步占槽步的多少？三条请求留下 5、5、6，块大小 4，最大长度 16。分页实际占用多少个位置槽，最后一块里空着多少？
- 完成标准：`7/16`；24 个位置槽；内部碎片 8。

<details>
<summary>参考解答</summary>

`14/32 = 7/16`。块数 `2+2+2 = 6`，`6×4 = 24`。碎片 `(4−1)+(4−1)+(4−2) = 8`。连续预留是 48，那 32 个空位是另一笔账。

</details>

### 练习 4：一轮能承诺几个 token

- 目标：接受率、封顶和草稿代价都进同一个期望。
- 限制：`α = 4/5`，`γ = 3`。先写 `P(X=k)` 再求期望。
- 题面：期望被接受的草稿数是多少？一轮期望产出多少 token？`c = 1/10` 时期望加速是多少？`α = 1` 时期望产出是多少？
- 完成标准：`244/125`，`369/125`，`738/325`（约 2.2708），以及 4。

<details>
<summary>参考解答</summary>

`P = (1/5, 4/25, 16/125, 64/125)`。草稿期望 `244/125 = 1.952`。加目标模型的一个 token 得 `369/125 = 2.952`。除以 `13/10` 得 `738/325 ≈ 2.2708`。`α = 1` 时不代分母为零的公式，产出 `3+1 = 4`。

</details>

### 练习 5：量化再还原

- 目标：缩放因子、最近整数、还原误差连在一起。
- 限制：分数。正中舍入远离 0；本组数用不到这条。
- 题面：权重 `2/5, −6/5, 1/5, 4/5`。对称 int8 的 `q` 和最大绝对误差是多少？对称 int4（`[-7, 7]`）的最大绝对误差是多少？只看后两个权重、组大小 2 时，`4/5` 的误差变成多少？
- 完成标准：`q = (42, −127, 21, 85)`，最大绝对误差 `2/635`；int4 为 `2/35`；分组后 `4/5` 的误差是 0。

<details>
<summary>参考解答</summary>

`s = 6/635`，误差 `(2/635, 0, 1/635, −2/635)`。int4 的 `s = 6/35`，误差 `(2/35, 0, 1/35, −2/35)`。后一组 `s = 4/635`，`4/5` 落到 127，还原后误差是 0。`(0, 1, 5)` 的非对称误差 `−1/254` 在正文里，脚本一并复核。

</details>

### 练习 6：三个时间

- 目标：第一个 token 只进 TTFT 一次。
- 限制：排队时间为 0。`TTFT = 200` 毫秒，`TPOT = 25` 毫秒，`N = 9`。
- 题面：端到端多少毫秒？这条请求的输出吞吐是多少 token 每秒？`TTFT + N × TPOT` 多算了什么？
- 完成标准：400 毫秒，22.5 token/s。多算的是已经包含在 TTFT 里的第一个 token，会得到 425 毫秒。

<details>
<summary>参考解答</summary>

`200 + 8×25 = 400`。`9 / 0.4 = 22.5`。`200 + 9×25 = 425`，第一个 token 的时间出现了两次。服务吞吐还要另测批量之后的墙钟，不能把 22.5 乘上批量。

</details>

## 本篇之外

实验记录的字段、线上曲线怎样和任务指标对照，仍按路线图留在各自的笔记。分布式切分的手算在 [分布式训练](03-分布式训练.md)。RoPE、SwiGLU 和 GQA 的结构公式不在本篇。Prefill 里把同一种注意力的中间矩阵留在片上、减少往返显存，是 FlashAttention 的题目；它不把注意力换成近似算法。本篇的带宽账看的是 decode 时权重和 KV 的搬运。束搜索共享前缀的块表、以及并行草稿头的代价模型，只点到名字。
