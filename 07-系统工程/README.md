## 完成时你能做什么

- 列出训练步中的 `tokens`、`inputs`、`logits`、`labels`、损失掩码，并说清每个形状。
- 说明数据并行的有效批量是各 worker 样本数之和，同步时梯度取平均。学习率是否随批量放大，是要做实验的选择。
- 用混合精度 Adam 的 16 字节一参数，算出朴素数据并行和 ZeRO-1/2/3 在给定并行度下的每卡模型状态，并指出 4 倍、8 倍是并行度很大时的极限。
- 对一次切开的矩阵乘指出列切分拼接输出、行切分对部分和做 all-reduce，并对给定的阶段数和微批数算出 GPipe 的气泡比例。
- 上线生成模型时分开记录质量与系统。质量来自任务测试；系统至少包括首 token 时间（TTFT）和生成速度。
- 用层数、KV 头数、头维、分配的位置数、批量和每元素字节数算出 KV cache，并说明批量很小时 decode 的权重矩阵乘落在带宽一侧。
- 有一次实验记录包含：代码版本、数据版本、种子、有效批量、损失定义（哪些 token 进了分母）、验证指标。别人据此可以讨论。不能一键复现时，记录写的是事实，而不是一个复现口号。

## 术语先固定在这里

**数据并行。** 每个 worker 有一份完整模型，读取不同小批量，反传得到梯度。同步时把梯度求和再除以 worker 数。朴素数据并行里，优化器状态在每张卡上各存一份。

**张量并行。** 把同一层的矩阵乘法拆到多张卡，每张卡保存权重的一块。它切的是层内的计算和权重。中间结果需要通信。

**流水线并行。** 按层把网络切成几段，分到不同卡上。一个批量再切成更小的块依次流过各段。卡在等待上游或下游时的空转叫气泡。

**ZeRO。** 仍在数据并行的框架里减少重复存储。ZeRO-1 切分优化器状态，ZeRO-2 再加上梯度，ZeRO-3 再加上参数。切得越细，单卡上的模型状态越少。论文第 7 节里，切到梯度为止的通信量与数据并行相同，连参数一起切才升到 1.5 倍。PyTorch 的 FSDP 在 `FULL_SHARD` 下切分参数、梯度和优化器状态，文档写明受 ZeRO stage 3 启发。手算在 [分布式训练](03-分布式训练.md)。

**KV cache。** 自回归解码时留下历史 token 的 key 和 value。新 token 计算自己的 query、key、value，其中 key 和 value 追加进缓存。精确算术下，注意力结果与不使用缓存时整段重算相同。省下的是对历史的重复计算，代价是缓存显存。

**连续批处理。** 生成长度不同。某个请求结束就释放它占用的槽，让给新请求。它提高服务吞吐。单个请求的条件分布定义不变。

**量化。** 用更少位数表示权重或激活，降低显存和一部分带宽。任务指标要重新测。

KV 字节、迭代级调度、分页和均匀量化的手算在 [推理优化](02-推理优化.md)。

**观测。** 训练至少看损失、进损失的 token 数、梯度范数、学习率。损失突然变 NaN、梯度范数持续爆炸、训练损失下降而验证损失上升，是三种不同的警报。线上把延迟和服务错误与质量抽样分开看。
