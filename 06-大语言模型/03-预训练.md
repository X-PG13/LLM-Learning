## 本篇要回答的问题

1. 预训练的损失为什么是被监督 token 上的平均负对数概率？按序列平均和按 token 平均，差的是哪一个分母？
2. 一份文档被复制四次时，精确去重怎样改变它在经验分布里的权重？
3. 两个集合的 MinHash 相等的概率，为什么等于它们的 Jaccard？
4. `C ≈ 6ND` 把一次乘加算成 2，`N` 不含哪些参数？序列长度接近宽度时，少算了哪一项？
5. 训练损失还在下降、验证损失已经上升时，该留下哪一个检查点？

## 目标仍是下一个 token

预训练在大规模文本上拟合条件分布 `p(x_t | x_<t)`。一段 token 的联合概率就是这些条件概率的乘积，开篇已经用链式法则写过。要最大化的是训练集上这些条件概率的对数，也就是最小化平均负对数似然。对数是 `ln`，单位是 nat。困惑度是 `exp(平均 NLL)`。

分母是被监督的 token 数，不是序列数，也不是文档数。填充和约定 A 里不参与损失的位置不进分母，和系统笔记里的 `ignore_index` 是同一条规定。两条序列各有两个被监督的位置，一共四项：

```text
序列 A：-ln 0.5 和 -ln 0.25，和为 ln 2 + ln 4 = ln 8
序列 B：-ln 0.5 和 -ln 0.5，和为 ln 4
四项的平均：(ln 8 + ln 4) / 4 = (5/4) ln 2 ≈ 0.866434
困惑度：exp(平均) = 2^{5/4} ≈ 2.378414
```

若误把分母写成序列数 2：

```text
(ln 8 + ln 4) / 2 = (5/2) ln 2 ≈ 1.732868
困惑度：2^{5/2} ≈ 5.656854
```

模型没有变，只是平均的方式变了。两条曲线不能放在一起比。`CrossEntropyLoss` 的默认 `reduction='mean'` 是对未忽略的位置平均；`sum` 会再乘上被监督 token 的个数。换 `reduction` 等于换了学习率的尺度，这件事在优化笔记里用批量的平均和求和算过。

打包把多篇文档拼进同一个长度固定的序列。约定 A 下，位置 `t` 的目标是 `t + 1`，不管这两个 token 是不是同一篇文档。没有文档边界时，下一篇的第一个 token 被当成上一篇的续写，这个条件概率在真实文本里并不存在。用一个分隔符或结束符把边界写成词表里的一个事件，损失才是在拟合「文档在这里结束」。分隔符占一个被监督位置，它进分母。

## 数据从文档变成 token

预训练的算法有一半在损失函数外面：什么文本以多大的概率成为那一个 token。一条可以复现的管道按这个顺序做。每一步都是一个明确的谓词或一个明确的采样比例，换一条规则就换了训练分布。

1. 解码。输入是文档，不是已经切好的 token。编码错误、缺页和嵌套的标记要在这里处理掉。
2. 质量过滤。语言、最短长度、重复行、乱码，都写成可以复算的谓词。阈值是管道的参数，不是模型的超参数的替身。
3. 精确去重。把文档规范化之后做哈希，哈希相同只留一份。规范化要写明：是否忽略大小写、是否压缩空白。两种规范化会留下不同的「重复」。
4. 近似去重。精确哈希留不住只改了一个词的副本。下面用 MinHash 估计 Jaccard，再用局部敏感哈希把估计值高的文档放在一起比较。
5. 去污染。评估集里的原文不应当出现在训练集里。字符串完全一致可以被这一步删掉；改写过的题目可以留下来。精确匹配没有证明评估是干净的。
6. 配比。每个来源有一个采样权重。一个来源被采样的 token 数，除以它去重之后的 token 数，就是它的 epoch。权重要求 100，来源里只有 50，不做重复就填不满。
7. 分词和打包。用最终要上线的那一个分词器数 token。不同分词器的困惑度不能比，开篇已经说过原因。

合成数据是配比表里的一个来源，不是免费的额外 token。它把生成模型自己的分布写回训练集。下面单独算一次混合。

### 精确去重改变的是权重

十篇文档，每篇 100 个 token，一共 1000。其中四篇是同一篇文本的副本，另外六篇各不相同。这份文本占训练 token 的 `400/1000 = 2/5`。

精确去重之后剩七篇、700 个 token。同一篇文本只占 `100/700 = 1/7`。它的 n-gram 在经验分布里的频率从 `0.4` 降到约 `0.142857`，模型用梯度看见它的次数也按这个比例减少。去重没有改变模型结构，改变的是损失在对谁平均。

Lee 等人指出，重复文档同时推高记忆，也让评估文本更有机会以另一种表面形式出现在训练里。本篇用上面的分数说明机制：频率是计数，不是「看过就算」。论文里的具体幅度依赖他们的语料和模型，换一份数据要重测。

### MinHash 等于 Jaccard 的概率

两篇文档各做成一个集合。词的二元组就够做例子。`"a b c d"` 的二元组是 `{ab, bc, cd}`，`"a b c e"` 的是 `{ab, bc, ce}`，`"x y z"` 的是 `{xy, yz}`。把它们编号：`ab=1, bc=2, cd=3, ce=4, xy=5, yz=6`。

```text
A = {1, 2, 3}
B = {1, 2, 4}
C = {5, 6}
```

Jaccard 相似度是 `|交集| / |并集|`。`A` 和 `B` 的交集是 `{1, 2}`，并集是 `{1, 2, 3, 4}`，相似度 `2/4 = 1/2`。`A` 和 `C` 的交集是空的，相似度是 0。

MinHash 用一个随机排列的最小值。实现里用一个看起来像随机的函数 `h` 代替排列：集合的签名是 `min { h(x) : x 在集合里 }`。两个集合的最小值相等，当且仅当并集里 `h` 最小的那个元素落在交集里。`h` 若把并集均匀地打乱，每个元素成为最小的概率相同，所以

```text
P(min h(A) = min h(B)) = |A ∩ B| / |A ∪ B|
```

多个独立的 `h` 组成一个签名向量。对应位置相等的比例，是 Jaccard 的估计。位置少的时候方差大，估计可以刚好等于真值，也可以偏得很远；相等的是期望，不是每一次。

取两个函数，模数 7：

```text
h1(x) = x mod 7
h2(x) = (2x) mod 7
```

`h2` 在 `{1, 2, 3, 4}` 上的值是 `2, 4, 6, 1`。

```text
A：min h1 = min(1, 2, 3) = 1，min h2 = min(2, 4, 6) = 2
B：min h1 = min(1, 2, 4) = 1，min h2 = min(2, 4, 1) = 1
C：min h1 = min(5, 6) = 5，min h2 = min(3, 5) = 3
```

`A` 和 `B` 的两个位置里有一个相等，估计是 `1/2`，和真值相同。`A` 和 `C` 两个位置都不相等，估计是 0，也和真值相同。这组函数是为了能手算而挑的，不是生产系统里的哈希族。生产里要用更多的独立函数，再把签名分带，只在同一带里做精细比较。带的个数和阈值决定「多像才会被送到一起」，也决定漏掉的近似重复有多少。

### 配比和合成数据

三个来源的采样权重是 `0.7, 0.2, 0.1`，预算 `D = 1000` 个 token。分到的数量是 700、200、100。若第三个来源去重之后只有 50 个 token，要凑满 100 就必须让它出现两个 epoch，或者把权重降下来。不写明 epoch，就不知道模型看见的是新文本还是同一段的第二遍。

合成数据再算一次混合。真实分布里某个稀有 token 的概率是 `0.1`。生成模型给出的概率是 `0.02`。训练集一半真实、一半合成时，这个 token 的频率变成

```text
0.5 * 0.1 + 0.5 * 0.02 = 0.06
```

稀有事件被稀释，没有被删除。若合成部分改成贪心解码，生成模型几乎只产生它的众数，稀有 token 在合成的那一半里可以是 0。再训一个模型去拟合这份混合物，目标已经不是原来的 `0.1`。下一轮若仍用新模型制造合成数据，频率还会再降。Shumailov 等人把这种迭代造成的分布收缩叫做模型坍缩。混入真实数据能减慢收缩，比例本身要出现在配比表里。

## 扩展规律是拟合，不是恒等式

Kaplan 等人在他们的解码器、WebText2 和训练设定下观察到：当另外两个因素不构成瓶颈时，交叉熵损失随非嵌入参数量 `N`、数据量 `D`、以及按某种方式分配的算力，大致呈幂律下降。幂的指数和常数依赖这份设定。他们报告的一种算力分配是，最优模型大小大约按 `C_min^{0.73}` 增长，增加的算力主要变成更多的参数，数据量的增长慢得多。正文里数据量随这份最优算力的一个拟合大约是 `C_min^{0.26}` 这一档。这些指数不是对所有语料和所有架构的定律。

Hoffmann 等人用三种估计重新画了这条前沿。三种做法都指向：算力增加时，参数量和 token 数应当一起放大，而不是只放大参数。他们用和 Gopher 相同的算力预算训练 Chinchilla：Gopher 是 280B 参数、约 300B token；Chinchilla 是 70B 参数、1.4T token。

```text
1.4 × 10^12 / (70 × 10^9) = 20
```

每参数约 20 个 token。这是他们实际训练那一个模型时用的比例。三种拟合给出的具体指数并不完全相同，40B 到 70B 都落在他们对那份算力的估计区间里。拿「20」去排另一次训练的预算之前，要写明数据、调度和用的是哪一种拟合。换数据或换架构之后，系数可以变。`6ND` 只负责把 `(N, D)` 换成浮点次数，它不决定损失，也不决定 20 这个比例。

## 6ND 在记什么

一次浮点运算是一次加法或一次乘法。矩阵乘里的一次乘加是 2。标准宽度下，`d_attn = d_model`，`d_ff = 4 d_model`，一层的非嵌入参数是注意力四个矩阵 `4 d²` 加上前馈两个矩阵 `8 d²`，共 `12 d²`。这和自注意力笔记里的参数个数是同一笔账，偏置和归一化是低阶项，不记在里面。

```text
N = 12 * n_layer * d_model²
```

每个这样的参数，对一个 token 的前向贡献约 2 次浮点运算，所以参数矩阵的前向是每 token `2N`。反向传播大约是前向的两倍，再加 `4N`。训练一个 token 大约是 `6N`。`D` 个 token：

```text
C ≈ 6 N D
```

`N` 按 Kaplan 等人的定义，不含词嵌入表，也不含位置嵌入。嵌入表是一次查表，不是 `V × d` 的乘法。输出投影如果是单独的 `(V, d)` 矩阵，它是真正的乘法。缩放规律的横轴可以不把它算进 `N`，浮点账仍要另加。前向是每 token `2 V d`。训练若按前向的三倍估计，就是 `6 V d`。

手算一个整数例子。`N = 10^8`，`D = 2 × 10^9`，每参数 20 个 token，和上面的比例对齐，只是模型小得多。

```text
C = 6 * 10^8 * 2 * 10^9 = 1.2 × 10^18
```

若这些矩阵乘在硬件上持续跑到每秒 `10^14` 次浮点运算，墙钟时间是

```text
1.2 × 10^18 / 10^14 = 1.2 × 10^4 秒 = 12000 秒 = 3 小时 20 分
```

`10^14` 是这个例子里的持续吞吐，不是某一张卡的峰值标称。峰值更高时，同样的 `C` 用时更短；持续吞吐只有峰值的一部分时，用时按那个比例拉长。

同一笔账可以拆到步。每步 `B = 2 × 10^5` 个 token，`10^4` 步，`D = B × 步数 = 2 × 10^9`。每步约 `6 N B = 1.2 × 10^14` 次运算，乘上步数仍是 `1.2 × 10^18`。画损失曲线时，横轴用见过的 token 还是用步，差的就是这个 `B`。中途把批量加倍，步和 token 就不再是同一把尺子。

只记前向、写成 `2ND`，会把训练少算 3 倍：`2 * 10^8 * 2 * 10^9 = 4 × 10^17 = C / 3`。激活检查点会把一部分前向再算一遍，硬件计数高于 `6ND`。扩展规律里的 `C` 通常仍按不重复计算的 `6ND` 记。两边比较之前要先声明用的是哪一种。

### 同一个 C，两种分法

`C = 1.2 × 10^18` 固定。

| 方案 | `N` | `D = C / (6N)` | 每参数 token |
| --- | --- | --- | --- |
| A | `10^8` | `2 × 10^9` | 20 |
| B | `4 × 10^8` | `5 × 10^8` | 1.25 |

浮点次数相同。哪一个损失更低，由扩展规律的拟合回答，不由 `6ND` 回答。Kaplan 的分配把预算更多地分给 `N`，Hoffmann 等人的分配让 `D` 随 `N` 一起长。方案 B 更接近前一种习惯，方案 A 更接近后一种比例。小模型上的 20 只说明算术，不说明这个 `N` 在那份数据上是最优的。

### 注意力的二次项没有在 6N 里

`6N` 只数了和参数矩阵相乘的那些运算。`Q Kᵀ` 和注意力权重乘 `V` 是激活和激活相乘。一个 token、一层、`d_attn = d_model` 时，这两次各是 `2 S d` 次浮点运算，前向合计 `4 n_layer S d`。和参数前向 `2N = 24 n_layer d²` 相比，比值是

```text
4 n_layer S d / (24 n_layer d²) = S / (6 d)
```

训练若仍按「反向约是前向的两倍」，每 token 的训练代价是

```text
6N * (1 + S / (6 d))
```

`d = 512`，`n_layer = 8`，`S = 1024`。

```text
N = 12 * 8 * 512² = 25165824
S / (6 d) = 1024 / 3072 = 1/3
```

`6ND` 少算了三分之一。同样的 `N = 10^8`、`D = 2 × 10^9` 若也处在这个比值上，训练代价是 `1.2 × 10^18` 的 `4/3`，即 `1.6 × 10^18`。

Kaplan 等人的表把上下文项写成 `2 n_layer n_ctx d_attn`，对应的是分数那一次矩阵乘，没有把乘 `V` 的那一次列进去。在他们的表里，这一项相对 `2N` 的比值是 `S / (12 d)`，所以他们说 `d_model` 远大于 `n_ctx / 12` 时可以略去。把乘 `V` 也算上，同一句「占比不大」要对着 `S / (6 d)` 看。`S = 1024`、`d = 512` 时，`S / (12 d) = 1/6`，`S / (6 d) = 1/3`，两项都不是可以略去的零头。上下文再加长，二次项先超过参数项。

输出投影另算。`V = 50257`，`d = 512`，八层那个小模型：

```text
前向的参数部分 2N = 50331648
前向的输出投影 2 * 50257 * 512 = 51463168
```

输出投影的前向已经略大于整个八层主体。把「`N` 不含嵌入」理解成「和词表相乘也不用算」，在这个尺寸上会少掉一半左右的前向。换成 `n_layer = 80`、`d = 8192`、同一个 `V`：

```text
N = 12 * 80 * 8192² = 64424509440
前向主体 2N = 128849018880
前向输出投影 2 * 50257 * 8192 = 823410688
```

输出投影只约是主体前向的 `0.006391`。大模型上它退回低阶，小模型上它不是。`6ND` 用在哪个尺寸，要带上这一项再决定能不能略去。

归一化、softmax、激活是逐元素运算，次数随 `n_layer * S * d` 增长，不随 `d²` 增长。宽度大时它们低于矩阵乘。它们不改变上面的主项该不该加上 `S / (6 d)`。

## 损失曲线在比较什么

能放在同一张图上的损失，必须共享分词器、`ln`、分母里有哪些位置，以及平均是按 token 还是按序列。差一个分母，前面已经差出 `2.378` 和 `5.657` 两种困惑度。

下面每步处理 `2 × 10^5` 个 token。表里的数是平均 NLL。

| 步 | 见过的 token | 训练 | 验证 |
| --- | --- | --- | --- |
| 100 | `2 × 10^7` | 3.50 | 3.55 |
| 200 | `4 × 10^7` | 3.00 | 3.10 |
| 400 | `8 × 10^7` | 2.50 | 3.05 |
| 800 | `1.6 × 10^8` | 2.10 | 3.20 |

验证损失在步 400 最低，是 3.05，困惑度 `exp(3.05) ≈ 21.1153`。步 800 的训练损失更低，验证损失升到 3.20，困惑度 `exp(3.20) ≈ 24.5325`。按训练损失留下最后一步，验证困惑度大约高出 `3.42`。这张表要留的是步 400 的参数。用验证曲线选择步数，和用验证误差选择正则系数是同一件事，见 [泛化、正则与模型选择](../04-经典机器学习/02-泛化正则化与模型选择.md)。早停怎样写进训练循环，仍是后面的主题。读曲线只需要这一个比较。

从 100 到 200，训练和验证一起下降。从 200 到 400，训练下降 0.50，验证只下降 0.05。从 400 到 800，训练再下降 0.40，验证上升 0.15。验证不再跟着训练走，说明后来见过的 token 在改进训练集上的拟合，没有改进这一份验证文本上的预测。重复数据很多个 epoch 时，会出现这种分叉：训练损失还能降，留出的新文本不再降。

一次尖峰和一条向上的验证曲线不是同一件事。尖峰要看它是否回到原来的下降趋势，以及那一步的数据里有没有空序列、错误的标签或突然放大的学习率。验证曲线整体抬高，换一个检查点解决不了数据问题。

验证 NLL 若低到 `0.05`，困惑度 `exp(0.05) ≈ 1.0513`，而训练 NLL 仍在 2 以上，模型几乎在默写验证文本。先回到去污染那一步，而不是把学习率调小。评估题和训练文档的关系，精确匹配删不掉的改写仍然要单独查。

## 参考代码

平均负对数似然的分母是位置数。`6ND` 的整数例子不需要浮点。

```python
import math


def mean_nll(nlls: list[float]) -> float:
    if not nlls:
        raise ValueError("no supervised tokens")
    return sum(nlls) / len(nlls)


def train_flops(n_params: int, n_tokens: int) -> int:
    """Kaplan 等人的非嵌入估计：每 token 约 6N，不含注意力的 S^2 项。"""
    return 6 * n_params * n_tokens
```

## 容易算错的地方

- 分母是被监督 token 数。四项损失除以 2 条序列，困惑度从约 `2.378` 变成约 `5.657`。
- 文档拼进同一序列时，边界上的「下一个 token」仍会计损失。没有分隔符，这个目标是假的续写。
- 精确去重改变的是频率。四份副本从 `2/5` 变成 `1/7`，不是「删掉重复就不影响分布」。
- MinHash 的期望等于 Jaccard。两个哈希函数的估计在例子里刚好是 `1/2`，换一组函数可以不是。
- `6ND` 的 `N` 是 `12 n_layer d²` 这种非嵌入参数。输出投影的 `2 V d` 在小模型上可以和 `2N` 一样大。
- 只写 `2ND` 少算了反向的那 4N。激活检查点让硬件计数高于 `6ND`，不等于缩放公式里的 `C` 改成了另一个定义。
- `S / (6 d) = 1/3` 时，把 `6ND` 当成总账会少掉三分之一。Kaplan 表里的上下文项只含分数矩阵乘，阈值是 `d` 相对 `n_ctx / 12`。
- 同一 `C` 的两种 `(N, D)` 谁的损失更低，不是 `6ND` 能回答的。20 token 每参数是 Chinchilla 那次训练的比例。
- 训练损失的最小值和验证损失的最小值可以不在同一步。表里是步 800 和步 400。

## 练习

### 练习 1：四项损失的两个分母

- 目标：平均方式是定义的一部分。
- 限制：纸笔。用 `ln`，困惑度用 `exp`。
- 题面：两项损失和为 `ln 8`，另两项和为 `ln 4`。按 4 个 token 平均，NLL 和困惑度是多少？按 2 条序列平均呢？
- 完成标准：`(5/4) ln 2` 和 `2^{5/4}`；`(5/2) ln 2` 和 `2^{5/2}`。四位小数约是 `0.8664`、`2.3784` 和 `1.7329`、`5.6569`。

<details>
<summary>参考解答</summary>

`ln 8 + ln 4 = 5 ln 2`。除以 4 是 `(5/4) ln 2`，除以 2 是它的两倍。困惑度是 2 的这个系数次方，因为 `exp(c ln 2) = 2^c`。

</details>

### 练习 2：四份副本的权重

- 目标：去重改的是计数。
- 限制：纸笔。
- 题面：十篇各 100 token，四篇相同。去重前这份文本占多少？精确去重后占多少？两个分数是什么？
- 完成标准：`2/5` 和 `1/7`。

<details>
<summary>参考解答</summary>

去重前 `400/1000 = 2/5`。去重后七篇，`100/700 = 1/7`。

</details>

### 练习 3：两个哈希里相等了几次

- 目标：估计的分子是签名里相等的位置数。
- 限制：纸笔。沿用 `h1(x) = x mod 7`，`h2(x) = (2x) mod 7`。
- 题面：`A = {1, 2, 3}`，`B = {1, 2, 4}`。Jaccard 是多少？两个 MinHash 里有几个相等？若有人用这一次的 `1/2` 证明任何哈希族都能得到 `1/2`，错在哪里？
- 完成标准：Jaccard `1/2`，一个位置相等。错在把一次估计当成了期望定理。

<details>
<summary>参考解答</summary>

交集 2，并集 4。`h1` 的最小值都是 1，`h2` 是 2 和 1。定理说的是随机 `h` 下相等的概率，不是手写的两个函数每一次都返回 `1/2`。

</details>

### 练习 4：把 6ND 乘出来

- 目标：前向、反向和墙钟时间分开。
- 限制：纸笔。`N = 10^8`，`D = 2 × 10^9`。
- 题面：`C` 是多少？若只记 `2ND`，少了几倍？持续吞吐 `10^14` 次每秒时，`C` 要多少秒？每步 `2 × 10^5` 个 token、共 `10^4` 步，见过的 token 是多少？
- 完成标准：`1.2 × 10^18`。少 3 倍。`12000` 秒。token 数是 `2 × 10^9`。

<details>
<summary>参考解答</summary>

`6 * 10^8 * 2 * 10^9 = 1.2 × 10^18`。`2ND = C/3`。`1.2 × 10^18 / 10^14 = 12000`。`2 × 10^5 * 10^4 = 2 × 10^9`，和 `D` 一致。

</details>

### 练习 5：同一算力的每参数 token

- 目标：`6ND` 不选择分配。
- 限制：纸笔。`C = 1.2 × 10^18`。
- 题面：`N = 10^8` 和 `N = 4 × 10^8` 时，`D` 各是多少？每参数多少 token？哪一个损失更低，这一问为什么不能由这两行除法回答？
- 完成标准：`D` 是 `2 × 10^9` 和 `5 × 10^8`。每参数 20 和 1.25。损失要由拟合或实验回答。

<details>
<summary>参考解答</summary>

`D = C / (6N)`。`1.2 × 10^18 / 6 × 10^8 = 2 × 10^9`，`1.2 × 10^18 / 2.4 × 10^9 = 5 × 10^8`。`5 × 10^8 / 4 × 10^8 = 5/4 = 1.25`。两种方案的浮点次数相同，损失还取决于数据、调度和扩展拟合。

</details>

### 练习 6：S/(6d) 和输出投影

- 目标：知道 `6N` 略去了什么。
- 限制：纸笔。`d = 512`，`n_layer = 8`，`S = 1024`，`V = 50257`。
- 题面：`N` 是多少？`S/(6d)` 是多少？输出投影的前向 `2Vd` 和主体前向 `2N` 哪一个更大？
- 完成标准：`N = 25165824`，比值 `1/3`。`2Vd = 51463168` 大于 `2N = 50331648`。

<details>
<summary>参考解答</summary>

`512² = 262144`，`12 * 8 * 262144 = 25165824`。`1024 / (6 * 512) = 1/3`。`50257 * 1024 = 51463168`，这就是 `2 * 50257 * 512`。主体前向是 `2 * 25165824 = 50331648`。

</details>

### 练习 7：留下哪一步

- 目标：验证损失的最小值不一定在最后一步。
- 限制：纸笔。用正文的表。
- 题面：哪一步的验证 NLL 最低？它和步 800 的验证困惑度各约是多少？步 400 已经见过多少 token？
- 完成标准：步 400。约 `21.1153` 和 `24.5325`。`8 × 10^7` 个 token。

<details>
<summary>参考解答</summary>

验证 NLL 是 3.55、3.10、3.05、3.20，最小在步 400。`exp(3.05)` 和 `exp(3.20)` 是这两个困惑度。`400 * 2 × 10^5 = 8 × 10^7`。

</details>

### 练习 8：混合物里的稀有 token

- 目标：合成数据改的是目标频率。
- 限制：纸笔。
- 题面：真实概率 `0.1`，合成概率 `0.02`，各占一半。混合频率是多少？若合成一半改成概率 0，混合频率又是多少？
- 完成标准：`0.06` 和 `0.05`。

<details>
<summary>参考解答</summary>

`0.5 * 0.1 + 0.5 * 0.02 = 0.06`。合成概率为 0 时是 `0.5 * 0.1 = 0.05`。两种都低于真实的 `0.1`。

</details>
