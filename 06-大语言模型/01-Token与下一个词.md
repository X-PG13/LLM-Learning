## 本篇要回答的问题

1. 一段文本的联合概率，怎样写成「下一个 token」的条件概率之积？
2. BPE 这样的子词算法在合并什么，为什么它不保证全局最优的切分？
3. 训练损失为什么是真实下一个 token 的负对数概率，它和 KL 是什么关系？
4. 温度作用在 logits 上时，小于 1 和大于 1 分别把分布变尖还是变平？
5. 为什么两个使用不同分词器的困惑度不能直接比大小？

## 模型在分配什么

把文本看成 token 序列 `x₁, x₂, …, xₙ`。模型要给这个序列一个概率。链式法则把它写成条件概率的乘积，不需要额外假设：

```text
p(x₁, …, xₙ) = p(x₁) · p(x₂ | x₁) · p(x₃ | x₁, x₂) · … · p(xₙ | x₁, …, xₙ₋₁)
```

因果语言模型学习的就是右侧每一项。给定已经确定的前缀，输出下一个 token 在词表上的分布。整段文本的概率是这些条件概率的乘积。条件概率的定义和期望、极大似然见 [概率](../02-数学基础/02-概率.md)。

`p(x₁)` 也是一个条件：条件是序列开始。实现里常用一个开始符，或者把第一个真实 token 的条件写成模型对空前缀的预测。使用哪一种，在数据格式里写明，不要在损失里隐式地换。

## 从字符串到整数

模型读到的是整数 id，不是汉字或单词本身。分词器负责两个方向：字符串变成 id 序列，id 序列解回字符串。

三种直观切法，各自把困难留在不同的地方。

- 按字符或字节：词表小，序列长。中文按字切时，序列长度大约就是字数。
- 按词：序列短，词表大，没见过的词要单独处理。中文没有空格，按词切还需要另一套分词。
- 按子词：词表里既有常见的长片段，也有用来拼出罕见串的短片段。序列长度和词表大小取一个折中。

实用检查有两条。第一，`decode(encode(s))` 是否回到 `s`，这是文本可逆。第二，特殊符号有没有被拆开。不同模型的分词器结果不同。要报告「这段中文用了多少 token」，就用你正在训练或调用的那一个分词器数一遍。不要借用别人给出的中英文倍率。

## BPE 在合并什么

这里用的是词内 BPE 的教学版本：语料按词和词频给出，初始符号是字符，反复合并当前最频繁的相邻对。合并不跨过词界。本例子的前三次合并都只有唯一的最高频对，所以不涉及平票规则。真实系统要规定平票时合并哪一对，否则词表不可复现。

这个教学版本省去了词尾标记。Sennrich 等 2016 的流程会使用词尾符号，使同一个字符出现在词尾和词中时可以不一样。GPT-2 则先按正则做预切分，再在字节上做 BPE，从而没有「未知词」。那些规则以论文和官方实现为准。下面的例子只保证你能手算合并。

语料：

| 词 | 次数 | 初始符号 |
| --- | --- | --- |
| cat | 5 | c a t |
| car | 4 | c a r |
| cap | 2 | c a p |
| map | 3 | m a p |

相邻对的次数：

```text
c a : 5 + 4 + 2 = 11
a t : 5
a r : 4
a p : cap 里 2 次，map 里 3 次，合计 5
m a : 3
```

第一次合并唯一的最高频对 `c a`，新符号记成 `ca`。

```text
ca t ×5
ca r ×4
ca p ×2
m a p ×3
```

第二次的次数：`ca t` 为 5，`ca r` 为 4，`ca p` 为 2，`m a` 为 3，`a p` 为 3。合并 `ca t`，得到符号 `cat`。此时 `car` 仍是 `ca r`，`cap` 仍是 `ca p`，`map` 仍是 `m a p`。

算法每次选当前最频繁的对，不回头搜索全局压缩率最好的词表。所以它是贪心的。第三次合并是练习。

## logits 与稳定的 log-softmax

词表一项对应一个实数打分 `zᵢ`，叫 logits。概率由 softmax 得到：

```text
pᵢ = exp(zᵢ) / Σⱼ exp(zⱼ)
```

每个 logits 加上同一个常数，分子和分母同乘 `exp(常数)`，分布不变。温度 `T > 0` 先把 logits 换成 `zᵢ / T`，再做 softmax。

直接计算 `exp(1000)` 会超出 IEEE-754 双精度的范围。稳定写法先减去最大值 `m`：

```text
log Σⱼ exp(zⱼ) = m + ln Σⱼ exp(zⱼ - m)
log pᵢ = zᵢ - log Σⱼ exp(zⱼ)
```

这就是 `log_softmax`。负对数似然直接取 `-log p_y`，不要先算出 `p_y` 再取对数，以免 `p_y` 下溢成 0。

一组可以手算核对的数：`z = (1, 2, 0)`，真实类别是下标 1（从 0 数，也就是值为 2 的那一维）。

| T | 近似概率（四位小数） |
| --- | --- |
| 1 | 0.2447, 0.6652, 0.0900 |
| 0.5 | 0.1173, 0.8668, 0.0159 |
| 2 | 0.3072, 0.5065, 0.1863 |

`T = 1` 时，真实类的 NLL 约为 0.4076，这一项单独的困惑度 `exp(NLL)` 约为 1.5032。四位小数的概率加起来是 0.9999，差的是舍入。`z = (1000, 1001, 999)` 与 `z = (1, 2, 0)` 是同一分布，因为 softmax 对整体平移不变，而稳定算法不会去算 `exp(1000)`。

`T = 0.5` 时概率更集中在已经最大的那一类，`T = 2` 时三类更接近。温度小于 1 让分布变尖，大于 1 让分布变平。贪心解码每步取概率最大的 token。最大值唯一时，它是 `T` 趋于 0 的极限。

top-k 只保留概率最高的 k 个 token，重新归一化。top-p 把概率从高到低累加，取最小的一组使累积概率至少为 `p`，再归一化。若最大的那一个 token 已经占了 0.9，而 `p = 0.9`，这一组可以只有它一个。温度、top-k、top-p 都是解码策略，不改变训练好的 logits 本身；它们改变的是从分布里取出 token 的方式。

## 交叉熵、KL 和困惑度

分布 `p` 的熵：

```text
H(p) = - Σᵢ pᵢ ln pᵢ
```

约定 `0 ln 0 = 0`。交叉熵和 KL 散度：

```text
H(p, q) = - Σᵢ pᵢ ln qᵢ
KL(p ‖ q) = Σᵢ pᵢ ln (pᵢ / qᵢ) = -H(p) + H(p, q)
```

因此 `H(p, q) = H(p) + KL(p ‖ q)`。`p` 固定时，比较两个模型 `q` 只需比较交叉熵，KL 只多减一个常数。

下一个 token 的训练目标把 `p` 取成真实 token 上的一点分布：真实类概率为 1，其余为 0。这时 `H(p) = 0`，交叉熵等于 `-ln q_y`，也等于 `KL(p ‖ q)`。批量损失是这些 NLL 的平均。平均时分母是参与损失的 token 数，填充不进去。这一点的实现见系统开篇。

困惑度定义为 `exp(平均 NLL)`，因为对数用的是 ln。若两步的条件概率分别是 `1/2` 和 `1/4`，

```text
平均 NLL = (ln 2 + ln 4) / 2
困惑度 = exp(平均 NLL) = sqrt(8) ≈ 2.8284
```

它等于每一步有效分支数 `1/p` 的几何平均：`1/p` 分别是 2 和 4，几何平均是 `sqrt(2 × 4) = sqrt(8)`。每一步都完全确定时，`p = 1`，困惑度是 1。每一步都在 3 个 token 上均匀，并且真实 token 是其中之一，困惑度是 3。

困惑度依赖分词。同一篇文章切得更碎，步数变多，每一步的条件也可能变容易，平均值的含义变了。比较两个模型时，使用同一个分词器和同一批原文。

更低的困惑度表示模型把更多概率分给了真实续写。抽取字段、遵守格式、事实是否成立，各自用任务测试。语言建模损失下降，说明的是续写概率，不自动说明这些任务变好。

## 训练时看见的前缀，和生成时看见的前缀

训练一个条件 `p(xₜ | x₁, …, xₜ₋₁)` 时，前缀用的是数据里的真实 token。这叫 teacher forcing。生成时，前缀是模型自己已经写下的 token。两边的条件分布不一致。这个差距叫 exposure bias。本篇只要求能指出前缀的来源不同。

标签比输入超前一个位置。序列 `今天 天气 很好` 若已经是 token id，约定 A 是：

```text
inputs: 今天  天气
labels: 天气  很好
```

位置 0 看见「今天」，预测「天气」。错一位把 labels 设成 inputs 本身时，模型在学习抄写当前 token，损失也可以下降。系统笔记用一个数值例子把这种「好看的损失」和正确的下一 token 损失对比出来。

## 特殊符号

名字在各家实现里不同，角色要分开记。

- 开始符：提供第一个真实 token 的条件，或标记序列开头。
- 结束符：让模型有一个「停止」可以预测。生成循环见到它就停。
- 填充符：把一个批次里的序列补到同一长度。它不应该贡献损失。
- 未知符：词表覆盖失败时的替身。字节级 BPE 用字节避开未知符，代价是罕见字符串可能变得更长。

## 容易算错的地方

- 温度除的是 logits。先 softmax 再除以温度，得到的不是 `z/T` 的 softmax。
- `T < 1` 变尖，`T > 1` 变平。把方向记反时，采样会看起来「温度调大了却更死板」。
- 困惑度只在同一分词器、同一原文、同一种对数底时比较。
- 一点分布上的交叉熵等于 NLL。`p` 不是一点分布时，熵那一项还在，交叉熵和 KL 差一个 `H(p)`。
- 贪心、top-k、top-p 是解码。它们不更新参数。

## 练习

### 练习 1：把四个 token 的联合概率展开

- 目标：链式法则写全每一项的条件。
- 限制：纸笔。
- 题面：展开 `p(x₁, x₂, x₃, x₄)`。指出哪一项的条件是空前缀。
- 完成标准：四项的条件分别是空前缀、`x₁`、`x₁x₂`、`x₁x₂x₃`。

<details>
<summary>参考解答</summary>

`p(x₁) p(x₂|x₁) p(x₃|x₁,x₂) p(x₄|x₁,x₂,x₃)`。第一项的条件是空前缀。

</details>

### 练习 2：做第三次 BPE 合并

- 目标：会在合并之后重新数相邻对。
- 限制：纸笔。不要直接看脚本。
- 题面：按正文，在合并出 `cat` 之后，列出相邻对次数，完成第三次合并，写出四个词现在的符号串。
- 完成标准：第三次合并的是 `ca r`，次数 4。四个词变成 `cat`、`car`、`ca p`、`m a p`。

<details>
<summary>参考解答</summary>

次数：`ca r` 为 4，`m a` 为 3，`a p` 为 3，`ca p` 为 2。最高且唯一的是 `ca r`。合并后：`cat ×5`、`car ×4`、`ca p ×2`、`m a p ×3`。`cap` 还没成为一词，因为它的对没有赢过 `car`。脚本 `check_bpe` 复核这一序列。

</details>

### 练习 3：平移不变

- 目标：用公式说明，而不是只代一组数。
- 限制：纸笔。
- 题面：证明 `softmax(z + c) = softmax(z)`，其中 `c` 加在每一个分量上。再用 `z = (1, 2, 0)` 和 `c = 5` 说明你的证明和数值一致。
- 完成标准：约分出 `exp(c)`。

<details>
<summary>参考解答</summary>

`exp(zᵢ + c) = exp(zᵢ) exp(c)`，分母的每一项同样乘 `exp(c)`，约掉。脚本对 `c = 5` 和整体平移到 `(1000, 1001, 999)` 都做了数值核对。后者同时要求实现先减最大值。

</details>

### 练习 4：读温度表

- 目标：从概率判断尖和平面。
- 限制：可以使用正文已经给出的四位小数。
- 题面：`z = (1, 2, 0)`。哪一个温度下，最大类的概率最高？`T = 2` 时三类概率为什么更接近？
- 完成标准：指出 `T = 0.5`，并说 logits 的差被除以更大的 `T` 之后变小。

<details>
<summary>参考解答</summary>

最大类概率：`T = 0.5` 时约 0.8668，高于 `T = 1` 的 0.6652 和 `T = 2` 的 0.5065。`T = 2` 时 `z/T = (0.5, 1, 0)`，原始差距被缩小，softmax 更平。

</details>

### 练习 5：两个 token 的困惑度

- 目标：用几何平均解释困惑度。
- 限制：纸笔。
- 题面：两步的条件概率是 `1/2` 和 `1/4`，对数是 ln。平均 NLL 和困惑度各是多少？
- 完成标准：困惑度是 `sqrt(8)`，并解释它是 `2` 和 `4` 的几何平均。

<details>
<summary>参考解答</summary>

NLL 是 `ln 2` 和 `ln 4`。平均后 `exp` 得到 `sqrt(8)`。`1/p` 分别是 2 和 4，几何平均是 `sqrt(8)`。脚本 `check_perplexity` 复核。

</details>

### 练习 6：分词器不同的两个损失

- 目标：拒绝一个无效的比较。
- 限制：文字。
- 题面：模型 A 和模型 B 的验证困惑度分别是 12 和 15，二者分词器不同。可以下的结论是什么？要比较续写概率，还缺哪一个条件？
- 完成标准：结论里出现「不能由此比较谁更会预测这段原文」。

<details>
<summary>参考解答</summary>

12 和 15 各自分词器内部有意义。分词不同，序列长度和每一步的词表都不同，困惑度不能直接比。要把同一原文用同一个分词器计算，或者比较的是任务指标而不是这个数。

</details>

### 练习 7：标出 inputs 和 labels

- 目标：约定 A 不靠记忆位置。
- 限制：纸笔。
- 题面：token id 是 `[7, 8, 9, 4]`。写出 `inputs` 和 `labels`。哪一个位置负责预测 4？
- 完成标准：`inputs = [7, 8, 9]`，`labels = [8, 9, 4]`。预测 4 的是看见 `[7, 8, 9]` 的那个位置。

<details>
<summary>参考解答</summary>

约定 A 丢掉最后一个作为输入、丢掉第一个作为标签。最后一个输入位置的标签是 4。

</details>

### 练习 8：损失低和任务差可以同时发生

- 目标：把困惑度和任务测试分开。
- 限制：开放题，没有唯一数值。
- 题面：模型甲的验证困惑度低于模型乙，但在「从简历里抽出电话号码」上更差。写出两种能够同时造成这件事的原因。
- 完成标准：两种原因都具体到数据或解码，而不是只写「泛化不好」。

<details>
<summary>参考解答</summary>

例如：验证集是网页正文，简历抽取不在这个分布里，甲更拟合网页。或者两边用了不同的分词器，困惑度本来就不能比，抽取失败来自电话号码被切碎。也可以是解码：甲用了很高的温度，续写概率在教师强制下仍然好，采样却不稳定。合格回答至少包含一条「验证文本和任务不是同一个分布」或一条「解码与教师强制不同」。

</details>
