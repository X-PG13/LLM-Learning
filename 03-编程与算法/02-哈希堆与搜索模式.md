## 本篇要回答的问题

1. 哈希表里「已经看过的值都在表里」这句话，怎样推出无序两数之和可以在平均 `O(n)` 里做完？冲突为什么让一次查找不再是 `O(1)`？
2. 只保留最大的 `k` 个元素时，为什么堆顶应当是这 `k` 个里最小的那个，总时间是 `O(n log k)` 而不是 `O(n log n)`？
3. 升序数组取平方之后，为什么每一步都可以从两端丢掉一个下标？
4. 在答案上二分时，可行谓词必须单调。`lo` 和 `hi` 各保证什么？把仍可行的 `mid` 减掉，会返回一个不可行的数吗？
5. 前缀和的表里如果没有空前缀 `0`，从下标 `0` 开始的那一段为什么会消失？

栈、队列、滑动窗口和前缀和用的是同一条纪律：先写不变量，再写下标怎么动。

## 哈希表

哈希表用一个函数 `h` 把键送进桶。本篇的教学实现是链式法：第 `h(key) mod m` 个桶是一个列表，冲突的键都挂在这一个列表上。查找要扫描这个列表，直到命中或走到末尾。

一次查找的时间取决于链有多长，不取决于「用了哈希」这四个字。`m` 随键的个数增长、并且键散开时，平均链长是常数，所以说平均 `O(1)`。所有键都进同一个桶时，这一次查找是 `O(n)`。没有做摊还、也没有假设散列均匀时，不要把最坏情况写成 `O(1)`。

`m = 3`，`h(k) = k`。键 `1, 2, 3` 落进三个桶：

```text
桶 0：3      因为 3 mod 3 = 0
桶 1：1
桶 2：2
```

键 `3, 6, 9` 全部落进桶 0，桶 1 和桶 2 是空的。查找 `9` 要顺着 `3 → 6 → 9` 走三步。平均 `O(1)` 在这组键上不成立。

Python 的 `dict` 会在装载因子过高时扩容并重散列。扩容那一次是 `O(n)`，分摊到前面的插入上可以是常数。开篇已经把「没有做摊还分析时，不把偶尔的贵操作叫 `O(1)`」写成规则。这里的链式例子是那句话的具体形状。

### 无序两数之和

开篇的双指针要求数组升序。数组无序、又允许用额外空间时，不变量改成：处理下标 `i` 之前，表里恰好是下标 `< i` 的值。

```python
def two_sum(nums: list[int], target: int) -> tuple[int, int] | None:
    """返回任意 i < j，使 nums[i] + nums[j] == target。不存在则返回 None。"""
    seen: dict[int, int] = {}
    for j, value in enumerate(nums):
        i = seen.get(target - value)
        if i is not None:
            return i, j
        seen[value] = j
    return None
```

`nums = [2, 7, 11, 15]`，`target = 9`。

```text
j = 0，值 2，需要 7，表是空的，记入 2 → 0
j = 1，值 7，需要 2，命中下标 0，返回 (0, 1)
```

每个下标最多进表一次，平均时间 `O(n)`，额外空间 `O(n)`。规格仍是任意一对。`[3, 3]`、目标 `6` 时，第二次看到 `3` 才命中第一次的下标，返回 `(0, 1)`。表里存的是下标，不是「这个值是否出现过」的布尔值；布尔值丢失了配哪一个位置。

先查再写入。若先把当前值写入，`target = 2 * nums[j]` 时会用自己配自己。`[3]`、目标 `6` 应当返回 `None`。下标 `0` 是合法命中。写成 `if i` 会把 `0` 当成没有找到，判断要用 `i is not None`。

## 堆

本篇的二叉堆是最小堆，用数组存完全二叉树。下标从 0 计：父节点是 `(i - 1) // 2`，左孩子是 `2i + 1`，右孩子是 `2i + 2`。不变量：每个节点的值都不大于它的孩子，因此根是全体最小。

插入把新值放在数组末尾，再向上交换，直到它不小于父节点。弹出根之后，把最后一个元素挪到根，再向下和较小的孩子交换，直到它不大于两个孩子。

插入 `4, 1, 3, 2`：

```text
[4]
[1, 4]           1 比父节点 4 小，交换
[1, 4, 3]        3 的父节点是 1，不交换
[1, 2, 3, 4]     2 先和父节点 4 交换，再看见根 1，停止
```

弹出：

```text
取出 1，末尾的 4 放到根：[4, 2, 3]
4 的较小孩子是 2，交换：[2, 4, 3]
再弹出 2，末尾的 3 放到根：[3, 4]
3 的孩子 4 更大，停止
```

两次弹出得到 `1` 然后 `2`。剩下的数组是 `[3, 4]`，根仍是当前最小。每个插入或弹出沿树高走，高度是 `floor(log2 n)`，一次是 `O(log n)`。

Python 的 `heapq` 就是这种最小堆。它不提供最大堆。要「当前最大」，可以把值取负再放进去，比较的是相反数，弹出来再取负还原。取负只适用于能取负的数；自己写比较时，不要一边用负号、一边又把原值放进同一个堆。

### 只保留最大的 k 个

流里要最大的 `k` 个，不必把全部 `n` 个数排序。用一个大小不超过 `k` 的最小堆。不变量：堆里是到目前为止最大的那些值，根是它们当中最小的，也就是下一个该被淘汰的。

新来的值不大于根，就丢掉。大于根，就弹出根，再把新值插进去。

`k = 2`，流是 `5, 1, 4, 2, 3`。

```text
5        堆 [5]
1        堆 [1, 5]
4 > 1    弹出 1，插入 4，堆 [4, 5]
2 ≤ 4    丢掉
3 ≤ 4    丢掉
```

留下 `4` 和 `5`。每个元素最多一次弹出和一次插入，时间 `O(n log k)`，额外空间 `O(k)`。全排序是 `O(n log n)` 时间。`k` 接近 `n` 时两者同阶，堆并不更快；`k` 远小于 `n` 时，`log k` 比 `log n` 小。

若要最小的 `k` 个，把堆改成最大堆，根是当前保留者里最大的，新值更小才替换根。方向反了，不变量的那一句也要反着写。

## 栈

栈是后进先出。不变量：弹出的永远是当前还在栈里、最后放进去的那个。数组的一端当栈顶，`append` 和 `pop` 都在这一端，均摊 `O(1)`。

下一个更大元素：对每个位置，找它右边第一个严格更大的值，没有则为 `None`。栈里存下标，从底到顶对应的值非增。不变量：栈里的下标都还没有找到下一个更大值，并且它们的值从底到顶非增。

```python
def next_greater(nums: list[int]) -> list[int | None]:
    """每个位置右边第一个严格更大的值；没有则为 None。"""
    answer: list[int | None] = [None] * len(nums)
    stack: list[int] = []
    for i, value in enumerate(nums):
        while stack and nums[stack[-1]] < value:
            answer[stack.pop()] = value
        stack.append(i)
    return answer
```

`nums = [2, 1, 2, 4, 3]`。

```text
2    栈 [0]
1    1 不大于 2，栈 [0, 1]
2    弹出 1，answer[1] = 2；栈顶的 2 不小于 2，压入。栈 [0, 2]
4    弹出两个 2，answer[2] = answer[0] = 4。栈 [3]
3    压入。栈 [3, 4]
结束  栈里剩下的位置保持 None
```

结果是 `[4, 2, 4, None, None]`。每个下标最多进栈一次、出栈一次，时间 `O(n)`。栈里若不是非增的，弹出时就不能断定「中间那些更小的值也已经不可能是答案」。

## 队列

队列是先进先出。用固定数组和两个下标时，`head` 是下一个弹出的位置，`tail` 是下一个写入的位置，`size` 是当前元素个数。容量 `cap` 下，下标按 `mod cap` 绕回。

不变量：若 `size > 0`，元素从 `data[head]` 起，沿增加方向取 `size` 个，经过末尾就绕回 `0`。`head == tail` 同时出现在「空」和「满」两种状态：空是 `size = 0`，满是 `size = cap`。只比较 `head` 和 `tail`，区分不了这两种状态。

容量 4，依次放入 `1, 2, 3`，弹出一次，再放入 `4, 5`。

| 操作 | `data` | `head` | `tail` | `size` |
| --- | --- | --- | --- | --- |
| 初始 | `[_, _, _, _]` | 0 | 0 | 0 |
| 放入 1 | `[1, _, _, _]` | 0 | 1 | 1 |
| 放入 2 | `[1, 2, _, _]` | 0 | 2 | 2 |
| 放入 3 | `[1, 2, 3, _]` | 0 | 3 | 3 |
| 弹出 1 | `[_, 2, 3, _]` | 1 | 3 | 2 |
| 放入 4 | `[_, 2, 3, 4]` | 1 | 0 | 3 |
| 放入 5 | `[5, 2, 3, 4]` | 1 | 1 | 4 |

最后 `head == tail == 1`，`size = 4`，队列是满的，顺序是 `2, 3, 4, 5`。再写入会覆盖还没弹出的 `2`。

另一种表示不存 `size`，浪费一个空位：`head == tail` 表示空，`(tail + 1) mod cap == head` 表示满。容量 4 时最多放 3 个元素。两种都对，混用会在满和空上差一个位置。

## 双指针：有序数组的平方

开篇的有序两数之和，丢掉一端是因为和太大或太小。这里换一个仍然只用两端的例子。`nums` 升序，返回每个元素的平方，并且结果升序。

升序数组的绝对值在靠近 0 的地方最小，最大绝对值一定在当前区间的某一端。不变量：还没写入的下标是闭区间 `[left, right]`，下一个该写入的位置应当放下这个区间里最大的平方，而它等于 `nums[left]²` 和 `nums[right]²` 中较大的那个。

```python
def sorted_squares(nums: list[int]) -> list[int]:
    """nums 升序。返回平方后的升序数组。"""
    left, right = 0, len(nums) - 1
    out = [0] * len(nums)
    for pos in range(len(nums) - 1, -1, -1):
        if abs(nums[left]) >= abs(nums[right]):
            out[pos] = nums[left] * nums[left]
            left += 1
        else:
            out[pos] = nums[right] * nums[right]
            right -= 1
    return out
```

`nums = [-4, -1, 0, 3, 10]`。

```text
16 和 100 比较，写入 100，right 左移
16 和 9  比较，写入 16， left 右移
1  和 9  比较，写入 9，  right 左移
1  和 0  比较，写入 1，  left 右移
剩下 0，写入 0
```

结果 `[0, 1, 9, 16, 100]`。每个下标写一次，时间 `O(n)`，额外空间是输出本身。数组不升序时，最大绝对值可以在中间，丢掉两端会漏掉它。

`abs` 在比较，平方在写入。两边都平方再比较，和比较绝对值在整数上一致，因为平方在 `[0, ∞)` 上递增。定宽整数里，平方可能先溢出，比较绝对值更稳。Python 的整数没有这个溢出。

## 滑动窗口

窗口是一段连续下标 `[left, right]`。右端只向右扩展，左端只向右收缩，每个下标最多进入一次、离开一次，时间 `O(n)`。能这样动，是因为约束对「再长大」或「再缩小」是单调的。

例：正整数数组里，和至少是 `target` 的连续子数组的最短长度。不存在则约定返回 `0`。正数保证：右端固定时，左端越往右，和越小。所以对每个 `right`，存在一个最右的 `left`，使 `[left, right]` 仍然够长；再收缩就不够。

```python
def min_length_at_least(nums: list[int], target: int) -> int:
    """正整数。返回和 >= target 的最短连续子数组长度；不存在则返回 0。"""
    best = 0
    left = 0
    total = 0
    for right, value in enumerate(nums):
        total += value
        while total >= target and left <= right:
            length = right - left + 1
            if best == 0 or length < best:
                best = length
            total -= nums[left]
            left += 1
    return best
```

不变量：`total` 是 `nums[left, right]` 的和；`best` 是所有已经完整收缩过的右端点里，最短可行长度。收缩放在 `while` 里，是因为一个 `right` 可能连着丢掉好几个 `left`。

`nums = [2, 3, 1, 2, 4, 3]`，`target = 7`。和第一次达到 7 是在右端下标 3，窗口 `[2, 3, 1, 2]` 的和是 8，长度 4。此后每次在仍然 `≥ 7` 时收缩：

| `left` | `right` | 和 | 当时的最短 |
| --- | --- | --- | --- |
| 0 | 3 | 8 | 4 |
| 1 | 4 | 10 | 4 |
| 2 | 4 | 7 | 3 |
| 3 | 5 | 9 | 3 |
| 4 | 5 | 7 | 2 |

答案是 2，对应最后一行的 `[4, 3]`。中间那一行和为 7 的 `[1, 2, 4]` 长度是 3，更长。有负数时，收缩不再保证和变小，这个 `while` 会丢掉仍可行的左端。

## 前缀和

`prefix[0] = 0`，`prefix[t] = nums[0] + … + nums[t - 1]`。下标 `l` 到 `r` 的和，两端都包含，是 `prefix[r + 1] - prefix[l]`。空前缀让 `l = 0` 时不用单写一条分支。

`nums = [1, 2, 3, 4]`，前缀是 `[0, 1, 3, 6, 10]`。下标 1 到 3 的和是 `2 + 3 + 4 = 9 = 10 - 1`。

和恰好为 `k` 的连续段有多少个：前缀 `s` 出现时，之前有多少个前缀等于 `s - k`，就有多少段以当前位置结尾、和为 `k`。表 `seen[s]` 记录这个前缀已经出现的次数，包含一开始的 `seen[0] = 1`。

```python
def count_subarrays_sum(nums: list[int], k: int) -> int:
    """连续子数组中和恰好为 k 的段数。"""
    seen = {0: 1}
    prefix = 0
    count = 0
    for value in nums:
        prefix += value
        count += seen.get(prefix - k, 0)
        seen[prefix] = seen.get(prefix, 0) + 1
    return count
```

`nums = [1, 1, 1]`，`k = 2`。

| 读入 | 前缀 | 查找 | 命中 | 累计 |
| --- | --- | --- | --- | --- |
| 1 | 1 | -1 | 0 | 0 |
| 1 | 2 | 0 | 1 | 1 |
| 1 | 3 | 1 | 1 | 2 |

两段是下标 `[0, 1]` 和 `[1, 2]`。整段和是 3，不算。第二次命中靠的是 `seen[0]`。若表从空开始，前缀 2 找不到 0，答案会变成 1，从下标 0 开始的那一段消失。

时间平均 `O(n)`，额外空间 `O(n)`。这是哈希表那一节的不变量用在前缀上：已经见过的前缀都在表里，并且次数是对的。

## 在答案上二分

开篇的 `lower_bound` 在有序数组里找位置。另一类二分不看数组是否有序，而看「这个候选值可不可行」。谓词 `feasible(x)` 必须单调：一旦某个 `x` 可行，任何更大的 `x` 也可行；一旦某个 `x` 不可行，任何更小的 `x` 也不可行。单调性不成立时，折半没有意义，漏掉的那一半里可能还有解。

例：把数组切成 `m` 段连续部分，每段至少一个元素，最小化「各段和的最大值」。`nums` 里都是正数。候选值是这个最大值的上限 `cap`。`cap` 至少是 `max(nums)`，否则单个元素都放不进任何一段；`cap` 至多是 `sum(nums)`，一整段就可行。`cap` 变大时，原来的切法仍然放得下，所以可行性单调。

```python
def feasible(nums: list[int], m: int, cap: int) -> bool:
    """能否切成至多 m 段，且每段和 <= cap。"""
    parts = 1
    total = 0
    for value in nums:
        if value > cap:
            return False
        if total + value > cap:
            parts += 1
            total = value
        else:
            total += value
    return parts <= m


def min_max_sum(nums: list[int], m: int) -> int:
    """连续切成 m 段，使各段和的最大值最小。"""
    lo, hi = max(nums), sum(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(nums, m, mid):
            hi = mid
        else:
            lo = mid + 1
    return lo
```

不变量：一切小于 `lo` 的候选都不可行；`hi` 可行；答案在闭区间 `[lo, hi]` 里。`mid` 可行时它仍可能是答案，所以 `hi = mid`，不能写成 `mid - 1`。`mid` 不可行时，`mid` 以及更小的都可以丢掉，`lo = mid + 1`。`lo == hi` 时只剩一个候选。

`nums = [7, 2, 5, 10, 8]`，`m = 2`。总和 32，最大元素 10。所有切成两段的方式里，各段和的最大值分别是：

```text
[7] | [2, 5, 10, 8]           max(7, 25) = 25
[7, 2] | [5, 10, 8]          max(9, 23) = 23
[7, 2, 5] | [10, 8]          max(14, 18) = 18
[7, 2, 5, 10] | [8]          max(24, 8) = 24
```

最小的那个最大值是 18。用谓词核对：`cap = 18` 时，`7 + 2 + 5 = 14`，再加 10 会超过 18，于是第二段是 `10 + 8 = 18`，恰好两段。`cap = 17` 时，第二段 `10 + 8 = 18 > 17`，不得不开第三段，不可行。

搜索过程：

| `lo` | `hi` | `mid` | 可行？ | 更新 |
| --- | --- | --- | --- | --- |
| 10 | 32 | 21 | 是 | `hi = 21` |
| 10 | 21 | 15 | 否 | `lo = 16` |
| 16 | 21 | 18 | 是 | `hi = 18` |
| 16 | 18 | 17 | 否 | `lo = 18` |

`lo == hi == 18`，停止。这和把六种切法都列出来的结果一致。`m = 1` 时答案就是总和 32，`m = 5` 时答案就是最大元素 10，因为每段只能放一个数。

若可行时写成 `hi = mid - 1`，同一次搜索会走到 17：`mid = 18` 被当成「已经过大」丢掉，最后 `lo == hi == 17`。17 不可行。开篇那个 `find_buggy` 是查找下标时把区间开闭和循环条件配错；这里是同一种错误落在答案空间上，返回值甚至不在可行集合里。

右端开闭要和更新一起定。本篇选择闭区间，`hi` 始终可行，所以可行时保留 `mid`。改成开区间也可以，条件、初值和更新要整组更换，不能只改其中一行。

## 参考代码

最小堆的向上、向下交换，用来对照上面的数组。`heapq` 弹出的序列应与 `heappop` 一致。

```python
def sift_up(heap: list[int], i: int) -> None:
    while i > 0:
        parent = (i - 1) // 2
        if heap[parent] <= heap[i]:
            break
        heap[parent], heap[i] = heap[i], heap[parent]
        i = parent


def sift_down(heap: list[int], i: int) -> None:
    n = len(heap)
    while True:
        left, right = 2 * i + 1, 2 * i + 2
        smallest = i
        if left < n and heap[left] < heap[smallest]:
            smallest = left
        if right < n and heap[right] < heap[smallest]:
            smallest = right
        if smallest == i:
            break
        heap[i], heap[smallest] = heap[smallest], heap[i]
        i = smallest
```

## 容易算错的地方

- 平均 `O(1)` 依赖散列和装载因子。同一条链上的三个键，查找就是三步。
- 无序两数之和先查再写入。先写入会让一个数和自己配对。
- 保留最大的 `k` 个时，堆是最小堆，根是「保留者里最差的」。写成最大堆会把大的先弹掉。
- 平方的双指针用了升序。两端的绝对值不再包住中间时，算法不成立。
- 滑动窗口的收缩用了「元素为正，收缩使和变小」。有负数时要换做法。
- 前缀和表里的 `0` 是空前缀，不是「数组里有一个 0」。漏掉它，从起点开始的段就消失。
- 答案上的二分：可行的 `mid` 仍可能是最小可行值。`hi = mid - 1` 会把它丢掉，本篇的例子因此返回 17。
- 环形队列里 `head == tail` 不能单独表示空。容量 4 若改成浪费一个空位，最多放 3 个元素。

## 练习

### 练习 1：无序两数之和的三次查询

- 目标：先查再写入，并且规格是任意一对。
- 限制：纸笔，不调用字典以外的结构。
- 题面：`two_sum([2, 7, 11, 15], 9)`、`two_sum([3, 3], 6)`、`two_sum([3], 6)` 各返回什么？
- 完成标准：`(0, 1)`、`(0, 1)`、`None`。

<details>
<summary>参考解答</summary>

第一组在下标 1 命中需要的 2。第二组在下标 1 命中已经写入的 3。第三组表是空的，写入之后循环结束，没有第二个 3。若在查之前写入，第三组会返回 `(0, 0)`，违反 `i < j`。

</details>

### 练习 2：同一条链

- 目标：把最坏情况从「平均」里分开。
- 限制：纸笔。`m = 3`，`h(k) = k`。
- 题面：键 `3, 6, 9` 各在哪个桶？查找 9 要比较几次键？若有人说这次查找是 `O(1)`，缺了哪一句假设？
- 完成标准：三个键都在桶 0，比较 3 次。缺的是「链长是常数」。

<details>
<summary>参考解答</summary>

`3 ≡ 6 ≡ 9 ≡ 0 (mod 3)`。链是 `3, 6, 9`，命中 9 时已经看过三个键。平均 `O(1)` 还要求装载因子有界并且键散开；这组键不散开。

</details>

### 练习 3：堆的数组和最大的两个

- 目标：根始终是堆里最小的。
- 限制：纸笔。
- 题面：最小堆依次插入 `4, 1, 3, 2` 之后，数组是什么？再弹出两次，先后得到哪两个数？用大小为 2 的最小堆处理 `5, 1, 4, 2, 3`，最后堆里是哪两个数？
- 完成标准：数组 `[1, 2, 3, 4]`；弹出 `1` 然后 `2`；留下 `4` 和 `5`。

<details>
<summary>参考解答</summary>

见正文两张过程。第二次弹出后剩下 `[3, 4]`。最大的两个用最小堆，根是 4 时，2 和 3 都不再进入。

</details>

### 练习 4：平方写到哪一端

- 目标：用两端的绝对值决定写入顺序。
- 限制：纸笔。
- 题面：`sorted_squares([-4, -1, 0, 3, 10])`。按从后往前的顺序写出五个平方。若数组改成 `[10, -4, 0]` 仍用同一函数，哪一条不变量先失败？
- 完成标准：`100, 16, 9, 1, 0`。未排序时最大绝对值不保证在两端。

<details>
<summary>参考解答</summary>

结果数组是 `[0, 1, 9, 16, 100]`，写入顺序相反。`[10, -4, 0]` 的最大绝对值 10 在左端，但中间的 4 比右端的 0 更大；函数仍只比较两端，会在错误的时机丢掉左端或右端。

</details>

### 练习 5：窗口长度

- 目标：收缩时更新答案，而不是只在循环外看一次。
- 限制：纸笔。
- 题面：`nums = [2, 3, 1, 2, 4, 3]`，`target = 7`。最短长度是多少？对应的两个元素是什么？若数组里允许负数，为什么不能继续用这个 `while`？
- 完成标准：长度 2，元素 4 和 3。负数使收缩不一定减小和。

<details>
<summary>参考解答</summary>

正文最后一行窗口是下标 4 到 5，和为 7。`[1, 2, 4]` 和也是 7，长度 3。有负数时，丢掉左端可能使和变大，最短窗口不一定是「收缩到不能再收缩」的那一个。

</details>

### 练习 6：空前缀

- 目标：`seen[0] = 1` 是一段具体的子数组，不是形式。
- 限制：纸笔。
- 题面：`nums = [1, 1, 1]`，`k = 2`。有空前缀时答案是多少？去掉 `seen[0]` 之后答案是多少？少掉的是哪一段？
- 完成标准：2 和 1。少掉下标 `[0, 1]`。

<details>
<summary>参考解答</summary>

前缀 2 要找 0，空前缀提供这一次。前缀 3 要找 1，这次不依赖空前缀。少掉的是前两个 1。

</details>

### 练习 7：把可行的中点丢掉

- 目标：看出 `hi = mid - 1` 会离开可行区域。
- 限制：纸笔。沿用 `[7, 2, 5, 10, 8]` 和 `m = 2`。
- 题面：`cap` 为 18 和 17 时，`feasible` 各是什么？若可行时执行 `hi = mid - 1`，正文那张搜索表会停在哪个返回值？这个值可行吗？
- 完成标准：18 可行，17 不可行。错误更新停在 17。

<details>
<summary>参考解答</summary>

18 分成 `[7, 2, 5]` 与 `[10, 8]`。17 需要三段。错误更新在 `mid = 18` 时把 `hi` 设成 17，随后 `lo` 也被推到 17，循环在 `lo == hi` 时结束。返回值没有被 `feasible` 接受。

</details>

### 练习 8：环形缓冲区能放几个

- 目标：空和满的编码要一起定。
- 限制：纸笔。
- 题面：容量 4。正文用 `size` 区分空和满，最多放几个？若改成 `head == tail` 表示空、`(tail + 1) mod 4 == head` 表示满，最多放几个？最后一次放入 5 之后，`head == tail` 表示哪一种？
- 完成标准：4 和 3。正文那一次是满，不是空。

<details>
<summary>参考解答</summary>

`size` 可以取到 4。浪费一个空位后，四个槽里必须留一个不当作元素，最多 3 个。放入 5 之后 `head` 和 `tail` 都是 1，同时 `size` 是 4；没有 `size` 的话，这个相等会被读成空。

</details>
