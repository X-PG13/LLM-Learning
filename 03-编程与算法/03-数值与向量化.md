## 本篇要回答的问题

1. float64 里，为什么 `1 + 2⁻⁵³` 等于 1，而 `1 + 2⁻⁵²` 不等于 1？float32 在 `2²⁴` 附近，为什么加 1 会消失？
2. 同一组三个数，从左加得 0，先加后两项再加第一项得 1。哪一条运算律在浮点里不成立？
3. 形状 `(2,)` 和 `(2, 1)` 加到同一张 `(2, 2)` 的矩阵上，为什么得到两张不同的矩阵？对齐从哪一边开始？
4. `(n, k)` 乘 `(k, m)` 要做多少次乘法？把三重循环换成矩阵乘的库函数，这个次数变不变？
5. 填充位置的值是 0 时，错误的平均错在分子还是分母？和调用方共享一行时，改一个元素会改掉谁？

开篇用大 O 判断一个算法在给定规模下能不能跑完，并提醒同样是 `O(n)`，常数仍可以差一个数量级。本篇处理阶已经够用时仍然会算错的几件事：间距、括号、广播轴和归约的分母。

## 可表示的数，以及它们的间距

Python 的 `float` 是 float64：1 位符号，11 位阶码，52 位存下来的尾数。最高位的 1 不占这 52 位。从 1 起、到 2 之前，相邻两个可表示数的间距是 `2⁻⁵²`，大约 `2.22 × 10⁻¹⁶`。这个间距叫做 1 处的机器精度。跨过一个 2 的幂，间距就翻一倍。它描述的是这一段上的相邻间距，不是一切量级上的绝对误差。

```python
def gap_at_one() -> tuple[bool, bool]:
    """1 附近：半个间距会消失，一个间距不会。"""
    lost = (1.0 + 2.0**-53) == 1.0
    kept = (1.0 + 2.0**-52) == 1.0
    return lost, kept
```

`gap_at_one()` 得到 `(True, False)`。`1 + 2⁻⁵³` 正好落在 1 和下一个可表示数的中点，1 的尾数是偶数，平局舍入之后回到 1。`1 + 2⁻⁵²` 就是下一个可表示数，它和 1 的差是 `2⁻⁵²`。

float32 把存下来的尾数收成 23 位。1 附近的间距是 `2⁻²³`，大约 `1.19 × 10⁻⁷`。训练里的张量经常是 float32。到了 `2²⁴ = 16777216`，间距已经是 2：可表示的数是 `16777216`、`16777218`，中间的 `16777217` 不存在。

两个 float32 数的精确和，用 float64 装得下。下面的函数先在 float64 里相加，再舍入回 float32，得到的就是一次 float32 加法。

```python
import struct


def f32(value: float) -> float:
    """舍入到 float32，再以 Python 的 float 返回。"""
    return struct.unpack("f", struct.pack("f", float(value)))[0]


def add32(left: float, right: float) -> float:
    return f32(f32(left) + f32(right))
```

| 表达式 | float32 的值 |
| --- | --- |
| `2²⁴` | 16777216 |
| `2²⁴ + 1` | 16777216 |
| `2²⁴ + 2` | 16777218 |
| `1 + 2⁻²⁴` | 1 |
| `1 + 2⁻²³` | `1 + 2⁻²³` |

`2²⁴ + 1` 落在两个可表示数的正中间。平局舍入到偶数尾数，`2²⁴` 的尾数是偶数，所以结果停在 `2²⁴`，这个 1 消失。`1 + 2⁻²⁴` 是 float32 在 1 处的半个间距，同样因为平局回到 1。`1 + 2⁻²³` 本身就是 1 的下一个 float32，它被保留。

因此加 1 有没有效果，取决于当前数量级上的间距。累加器已经长到 `2²⁴` 之后，再往 float32 里逐个加 1，和保持不动。

## 加法不再满足结合律

实数里 `(a + b) + c = a + (b + c)`。浮点加法每次都舍入，括号换了，舍入发生的位置就换了。

float64 在 `2⁵³` 处的间距是 2。`2⁵³ + 1` 同样落在两个可表示数正中间，舍入到偶数尾数之后回到 `2⁵³`。

```python
def sum_left(values: list[float]) -> float:
    """从左到右。括号是 ((…) + 下一项)。"""
    total = 0.0
    for value in values:
        total += value
    return total
```

令 `big = float(2**53)`。列表是 `[1.0, big, -big]`。

| 步骤 | 运算 | 结果 |
| --- | --- | --- |
| 起点 | 0 | 0 |
| 加 1 | `0 + 1` | 1 |
| 加 `2⁵³` | `1 + 2⁵³` | `2⁵³`，这个 1 被间距吞掉 |
| 加 `-2⁵³` | `2⁵³ + (-2⁵³)` | 0 |

从左加得到 0。先加后两项：`big + (-big)` 是 0，再加 1 得到 1。两个结果都是这三次加法的某种括号，差是 1。没有写明顺序时，不要把其中一个叫做「这组数的和」。

十进制的 0.1 写成二进制是无限循环，float64 保存离它最近的那个可表示数。把这个数从左加十次：

```python
def sum_tenths() -> float:
    total = 0.0
    for _ in range(10):
        total += 0.1
    return total
```

`sum_tenths()` 等于 `1 - 2⁻⁵³`，不等于 1。差就是 1 下面的那一个单位。`==` 会失败。这不是循环写错了，是 0.1 从进入 float64 的那一刻起就已经不是十进制的十分之一。

float32 上同一条结合律用 `2²⁴` 演示。`(2²⁴ + 1) + (-2²⁴)` 先把 1 舍掉，再和自己的相反数抵消，得到 0。`(2²⁴ + (-2²⁴)) + 1` 得到 1。

```python
def float32_associativity() -> tuple[float, float]:
    big = float(2**24)
    left = add32(add32(big, 1.0), -big)
    right = add32(add32(big, -big), 1.0)
    return left, right
```

返回值是 `(0.0, 1.0)`。

库里的求和可以选择别的括号，例如两两相加，以减少舍入。它没有义务复现从左加的那一个结果。测试若要锁定某一种和，就锁定那种括号；若只要求接近一个数学值，就写上容差。

## 容差回答的是哪一个问题

```python
def almost_equal(left: float, right: float, atol: float, rtol: float) -> bool:
    """|left - right| <= atol + rtol * |right|。right 是当作标准的那个数。"""
    return abs(left - right) <= atol + rtol * abs(right)
```

`sum_tenths()` 和 1 的绝对差是 `2⁻⁵³`。`atol = 10⁻¹²`、`rtol = 0` 时，`almost_equal` 为真。两个容差都是 0 时，它和 `==` 一样为假。

相对容差按右边那个数的量级缩放。`big` 和 `big + 2` 在 float64 里是两个不同的整数，绝对差是 2。`atol = 0`、`rtol = 10⁻⁹` 时，门槛是 `10⁻⁹ × (2⁵³ + 2)`，大约 `9.007 × 10⁶`。绝对差 2 仍落在门槛里，函数返回真。这两个数若是 token 的个数，比较要用精确相等。

因此：

- 损失、概率这一类连续量，同时给出 `atol` 和 `rtol`。门槛写成公式，不写「大约相等」。
- 个数、下标、类别编号用精确相等。它们不是舍入误差。
- 一种实现声称自己是从左加，就和 `sum_left` 比精确值，或者把允许的括号写进规格。

## NaN 不会刷新最小值

`float("nan") == float("nan")` 是假。NaN 和任何数比大小也是假，包括和它自己。

```python
def keep_if_smaller(best: float, loss: float) -> float:
    """loss 比 best 小才替换。NaN 比大小为假，所以留着原来的 best。"""
    if loss < best:
        return loss
    return best
```

`keep_if_smaller(1.0, float("nan"))` 仍是 1.0。一次已经变成 NaN 的损失不会把记录里的最小值更新成 NaN，旧的有限值留在那里。检查要用 `math.isnan`，不能从「最小值没变」推出这一步仍然是有限的。

一个 NaN 加进 `sum_left`，结果是 NaN。后面的有限数加不回来。

## 广播从右边对齐

按元素相加时，两个形状从右边对齐，缺的维在左边补 1。某一维上的两个长度必须相等，或者其中一边是 1。1 那一边沿着这一维拉长。两边都不等于对方、又都不是 1，这一对形状不能相加。

```python
def broadcast_shapes(left: tuple[int, ...], right: tuple[int, ...]) -> tuple[int, ...]:
    """右对齐。不能广播时抛出 ValueError。"""
    width = max(len(left), len(right))
    a = (1,) * (width - len(left)) + left
    b = (1,) * (width - len(right)) + right
    result = []
    for x, y in zip(a, b):
        if x != y and x != 1 and y != 1:
            raise ValueError((left, right))
        result.append(max(x, y))
    return tuple(result)
```

| 左 | 右 | 对齐之后 | 结果 |
| --- | --- | --- | --- |
| `(2, 3)` | `(3,)` | `(2, 3)` 与 `(1, 3)` | `(2, 3)` |
| `(2, 3)` | `(2,)` | `(2, 3)` 与 `(1, 2)` | 不能广播，3 对 2 |
| `(2, 3)` | `(2, 1)` | 已对齐 | `(2, 3)` |
| `(2, 3, 4)` | `(3, 1)` | `(2, 3, 4)` 与 `(1, 3, 1)` | `(2, 3, 4)` |
| `(2, 3, 3)` | `(3,)` | `(2, 3, 3)` 与 `(1, 1, 3)` | `(2, 3, 3)`，加在最后一维 |

最后一行是容易漏掉的情况。结果形状合法，只说明每一维都兼容。长度为 3 的向量没有写出轴，右对齐把它放进最后一维。若最后一维是词表、这个 3 本该是时间，加法会成功，加到的轴是错的。时间和词表都是 3 时，`(3,)` 和 `(3, 1)` 都能广播成 `(2, 3, 3)`，两张结果不同。长度碰巧相等时，形状检查代替不了轴。

同一件事用一张小矩阵就能算完。`matrix` 是 `[[1, 2], [3, 4]]`，`vector` 是 `[10, 0]`。

```python
def add_on_axis(matrix: list[list[int]], vector: list[int], axis: int) -> list[list[int]]:
    """axis 0：每一行加同一个数。axis 1：每一列加向量里对应的数。"""
    row_count = len(matrix)
    col_count = len(matrix[0])
    if axis == 0 and len(vector) != row_count:
        raise ValueError("axis 0")
    if axis == 1 and len(vector) != col_count:
        raise ValueError("axis 1")
    out = []
    for i in range(row_count):
        row = []
        for j in range(col_count):
            extra = vector[i] if axis == 0 else vector[j]
            row.append(matrix[i][j] + extra)
        out.append(row)
    return out
```

形状 `(2,)` 右对齐到 `(2, 2)` 上，就是 `axis = 1`。10 加在第一列，0 加在第二列：

```text
[[11, 2],
 [13, 4]]
```

形状 `(2, 1)` 是 `axis = 0`。10 加在第一行的两列，0 加在第二行：

```text
[[11, 12],
 [ 3,  4]]
```

记号约定里 `y = x @ W.T + b`，`b` 的形状是 `(out_features,)`，加在最后一维，也就是特征维。批次大小若碰巧等于 `out_features`，一个本该按样本加的、长度相同的向量，会沿着特征维加上去，并且不报错。要按样本加，形状里得留出那个 1，写成 `(batch, 1)`，不能靠长度相同来代替轴。

## 向量化没有少做乘法

矩阵乘的定义就是一串点积。`left` 的形状是 `(n, k)`，`right` 的形状是 `(k, m)`，每个输出元素做 `k` 次乘法，一共 `n · m · k` 次。

```python
def matmul(left: list[list[int]], right: list[list[int]]) -> tuple[list[list[int]], int]:
    """返回乘积，以及乘法次数。left 是 (n, k)，right 是 (k, m)。"""
    row_count = len(left)
    inner = len(right)
    col_count = len(right[0])
    if any(len(row) != inner for row in left):
        raise ValueError("inner dimension")
    product = []
    multiplies = 0
    for i in range(row_count):
        row_out = []
        for j in range(col_count):
            total = 0
            for t in range(inner):
                total += left[i][t] * right[t][j]
                multiplies += 1
            row_out.append(total)
        product.append(row_out)
    return product, multiplies
```

`[[1, 2, 3], [4, 5, 6]]` 乘 `[[1, 0], [0, 1], [1, 1]]`。左上角是 `1×1 + 2×0 + 3×1 = 4`。四个输出是：

```text
[[4,  5],
 [10, 11]]
```

乘法次数是 `2 × 2 × 3 = 12`。

把这三重循环换成库里的一次矩阵乘，这 12 次乘法还在。变的是它们不再由解释器逐次分发，而是进一段连续的数值内核。形状放大到 `(n, k)` 和 `(k, m)` 时，经典算法的乘法次数仍是 `n · m · k`，也就是 `O(nmk)`。分块改变的是这一次乘法所用的数是否还在缓存里，常数会变，这个次数不变。

存在少做乘法的算法，例如 Strassen。常见的矩阵乘实现做的是分块之后的经典乘法，次数仍按 `n · m · k` 计。调用了矩阵乘，先按这个次数看阶，再去计时。开篇的规则在这里不变：先用阶排除不够的算法，再决定这段循环要不要交给数值内核。

点积是同一句话的短形式。长度 `n` 的点积是 `n` 次乘法，向量化之后还是 `n` 次。它比 Python 循环快，是因为常数，不是因为变成了 `O(log n)`。

## 归约的分母

平均的不变量要写成两句：分子是哪些位置的和，分母是这些位置的个数。分配到的长度可以更大，多出来的位置不进入任何一句。

```python
def masked_sum(rows: list[list[int]], mask: list[list[int]]) -> tuple[int, int]:
    """mask 为 1 的位置才进入分子。返回 (分子, 分母)。"""
    total = 0
    count = 0
    for row, bits in zip(rows, mask):
        for value, bit in zip(row, bits):
            if bit:
                total += value
                count += 1
    return total, count


def sum_all(rows: list[list[int]]) -> tuple[int, int]:
    """每个已分配的位置都计入，包括填充。"""
    total = 0
    count = 0
    for row in rows:
        for value in row:
            total += value
            count += 1
    return total, count
```

`rows = [[1, 3, 0], [5, 7, 0]]`，`mask = [[1, 1, 0], [1, 1, 0]]`。第三列是填充。

| 算法 | 分子 | 分母 | 均值 |
| --- | --- | --- | --- |
| `masked_sum` | 16 | 4 | 4 |
| `sum_all` | 16 | 6 | `8/3` |

这一次填充值是 0，所以分子碰巧相同，错只出现在分母：`8/3` 比 4 小，是因为 6 把两个不该计的位置算进了平均。填充位置若不是 0，分子也会变。不能从「这次分子一样」推出掩码可以不看。

分母取分配长度，和广播加错轴是同一类错误：程序能跑完，输出的形状也对，参与运算的那一组位置不是规格里的那一组。

## 共享同一行

`matrix[0]` 取出的是那一行这个列表本身，不是一份新的数。不变量：在复制之前，`row` 和 `matrix[0]` 是同一个对象。改 `row[0]` 就是改调用方的矩阵。

```python
def write_through(matrix: list[list[int]]) -> list[list[int]]:
    row = matrix[0]
    row[0] = 9
    return matrix


def write_on_copy(matrix: list[list[int]]) -> tuple[list[list[int]], list[int]]:
    row = matrix[0][:]
    row[0] = 9
    return matrix, row
```

从 `[[1, 2], [3, 4]]` 出发。`write_through` 之后矩阵是 `[[9, 2], [3, 4]]`。`write_on_copy` 之后矩阵仍是 `[[1, 2], [3, 4]]`，返回的那一行是 `[9, 2]`。元素是整数，切片得到的新列表和原来的行不再共享这几个格子。

数值库里的切片常常是原存储上的一块视图，就地加法会写回那块存储。上面两个函数把这件事用列表写出来：规格若是「不修改输入」，测试要在调用之后检查调用方的矩阵；规格若是「就地改写」，测试就检查同一对象。两种都对，混用时函数返回了新数，调用方的输入也变了。

## 容易算错的地方

- 把 `2⁻⁵²` 当成一切量级上的绝对误差。`2⁵³` 附近，float64 的间距已经是 2。
- 用 `==` 判断十个 `0.1` 的和是不是 1。这个从左加的结果是 `1 - 2⁻⁵³`。
- 用很松的相对容差比较两个计数。`2⁵³` 和 `2⁵³ + 2` 的相对差很小，它们仍是两个整数。
- 两个维的长度相同，广播就不报错。`(2, 3, 3)` 加上 `(3,)`，加到的是最后一维。
- 批次大小等于特征数时，`(batch,)` 和 `(out_features,)` 长得一样。按样本加要写成 `(batch, 1)`。
- 换成矩阵乘之后不再数 `n · m · k`。库函数没有把经典乘法的次数降一阶。
- 填充值是 0，分子没变，就认为掩码不影响平均。本篇的例子里分母从 4 变成了 6，均值从 4 变成 `8/3`。
- 把 `matrix[0]` 交给另一个名字之后就地修改。调用方的第 0 行会变成 9。
- 用 `loss < best` 看守 NaN。比较结果是假，记录里会留下更新前的有限值。

## 练习

### 练习 1：1 附近和 `2²⁴` 附近

- 目标：间距随量级变化。
- 限制：先写预测，再运行 `gap_at_one` 和 `f32`。
- 题面：`1 + 2⁻⁵³` 和 `1 + 2⁻⁵²` 哪些等于 1？float32 里，`2²⁴`、`2²⁴ + 1`、`2²⁴ + 2` 各是多少？
- 完成标准：等于 1 的是加 `2⁻⁵³`。float32 的三个值是 16777216、16777216、16777218。

<details>
<summary>参考解答</summary>

`gap_at_one()` 是 `(True, False)`。`2⁻⁵²` 是 float64 在 1 处的间距，加上之后不等于 1。float32 在 `2²⁴` 处的间距是 2，`+ 1` 落在正中间，舍入后仍是 16777216，`+ 2` 得到 16777218。

</details>

### 练习 2：三种括号里的两种

- 目标：把结合律的失败写成两个具体的数。
- 限制：纸笔。`big = float(2**53)`，不要用整数运算。
- 题面：`sum_left([1.0, big, -big])` 是多少？`1.0 + (big + (-big))` 是多少？差是从哪一步开始出现的？
- 完成标准：0 和 1。差出现在 `1 + big` 被舍入成 `big` 的那一步。

<details>
<summary>参考解答</summary>

从左加的第二步把 1 吞掉，第三步得到 0。先把 `big` 和 `-big` 抵消，得到 0，再加 1 得到 1。整数里的 `2**53 + 1` 不会发生这次舍入，所以题目要求 `float`。

</details>

### 练习 3：容差的门槛

- 目标：绝对容差和相对容差各放过什么。
- 限制：可以运行。门槛按 `almost_equal` 的公式算。
- 题面：`sum_tenths()` 和 1 的绝对差是多少？`atol = 10⁻¹²`、`rtol = 0` 时算不算接近？`atol = 0`、`rtol = 10⁻⁹` 时，`big` 和 `big + 2` 算不算接近？若这是两个计数，该用哪一种比较？
- 完成标准：差是 `2⁻⁵³`。第一问算接近。第二问也算接近，但计数必须用精确相等。

<details>
<summary>参考解答</summary>

`sum_tenths()` 等于 `1 - 2⁻⁵³`，绝对差小于 `10⁻¹²`。`big + 2` 与 `big` 的绝对差是 2，`10⁻⁹ × |big + 2|` 远大于 2，所以相对容差把它们判成接近。计数的规格是精确相等，不用这个门槛。

</details>

### 练习 4：五对形状

- 目标：右对齐，并且合法不等于轴正确。
- 限制：纸笔，不调用数值库。
- 题面：写出 `broadcast_shapes` 对这五对的结果：`(2, 3)` 与 `(3,)`，`(2, 3)` 与 `(2,)`，`(2, 3)` 与 `(2, 1)`，`(2, 3, 4)` 与 `(3, 1)`，`(2, 3, 3)` 与 `(3,)`。最后一对加在哪一维？
- 完成标准：`(2, 3)`，不能广播，`(2, 3)`，`(2, 3, 4)`，`(2, 3, 3)` 且加在最后一维。

<details>
<summary>参考解答</summary>

`(2,)` 补成 `(1, 2)` 之后，3 和 2 对不上。`(3, 1)` 补成 `(1, 3, 1)`，中间一维对齐时间、最后一维拉长。`(3,)` 补成 `(1, 1, 3)`，对齐的是最后一维。时间和词表都是 3 时，这一对不会报错。

</details>

### 练习 5：同一个向量加两次

- 目标：轴是规格的一部分。
- 限制：纸笔。
- 题面：`matrix = [[1, 2], [3, 4]]`，`vector = [10, 0]`。`add_on_axis` 在 `axis = 1` 和 `axis = 0` 时各得到什么？哪一个对应形状 `(2,)` 的右对齐？
- 完成标准：`[[11, 2], [13, 4]]` 和 `[[11, 12], [3, 4]]`。右对齐对应 `axis = 1`。

<details>
<summary>参考解答</summary>

`axis = 1` 时 10 加在第一列，0 加在第二列。`axis = 0` 时 10 加在第一行的两列，0 加在第二行。`(2,)` 对齐到列，所以是前一张。

</details>

### 练习 6：数乘法

- 目标：向量化不改变经典乘法的次数。
- 限制：纸笔。
- 题面：`matmul([[1, 2, 3], [4, 5, 6]], [[1, 0], [0, 1], [1, 1]])` 的乘积和乘法次数是多少？若改成库里的矩阵乘，次数变不变？
- 完成标准：`[[4, 5], [10, 11]]`，12 次，不变。

<details>
<summary>参考解答</summary>

左上角 `1 + 0 + 3 = 4`，右上角 `0 + 2 + 3 = 5`，左下角 `4 + 0 + 6 = 10`，右下角 `0 + 5 + 6 = 11`。`2 × 2 × 3 = 12`。库函数做的仍是这 12 次，只是不在解释器里逐次分发。

</details>

### 练习 7：填充不是 0

- 目标：分子和分母分开看。
- 限制：纸笔。
- 题面：正文的 `rows` 和 `mask` 下，两种算法的 `(分子, 分母)` 是多少？若把两个填充位置从 0 改成 100，`masked_sum` 和 `sum_all` 的分子各是多少？
- 完成标准：原来是 `(16, 4)` 和 `(16, 6)`。改成 100 之后，掩码分子仍是 16，`sum_all` 的分子是 216。

<details>
<summary>参考解答</summary>

掩码为 1 的四个数是 1、3、5、7，和为 16，填充不进入 `masked_sum`。`sum_all` 多加两个 100，分子是 `16 + 200 = 216`，分母仍是 6。填充为 0 时分子相同，只是这一组数的巧合。

</details>

### 练习 8：谁被写到了

- 目标：复制之前，两个名字是同一行。
- 限制：纸笔。
- 题面：`matrix = [[1, 2], [3, 4]]`。调用 `write_through` 之后矩阵是什么？对一份相同的初始矩阵调用 `write_on_copy`，矩阵和返回的行各是什么？`keep_if_smaller(1.0, float("nan"))` 返回什么？
- 完成标准：`[[9, 2], [3, 4]]`。复制那一次矩阵不变，行是 `[9, 2]`。NaN 那一次返回 1.0。

<details>
<summary>参考解答</summary>

`write_through` 里的 `row` 就是 `matrix[0]`，`row[0] = 9` 写进调用方。`matrix[0][:]` 是新列表，写 9 只出现在返回值里。NaN 与 1.0 比大小的结果是假，`best` 保持 1.0。

</details>

## 本篇之外

很多指数相加时先减去最大值，那一组 logits 在 [Token 与下一个词](../06-大语言模型/01-Token与下一个词.md)，本篇不重算。先形成 `AᵀA` 会把条件数平方，见 [线性代数](../02-数学基础/01-线性代数.md)。那是问题本身的敏感程度；本篇的 1 被吃掉，是间距和括号造成的，良态的三个数也会发生。哈希、堆与搜索仍在 [哈希、堆与搜索模式](02-哈希堆与搜索模式.md)。本篇的间距、两种求和、容差、广播、矩阵乘次数、掩码分母和别名由 `check_numerics` 复核。
