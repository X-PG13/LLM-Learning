## 本篇要回答的问题

1. 给定输入规模，怎样用大 O 判断这个解能不能在约束内跑完？
2. 循环不变量是哪一句必须在每次迭代前后都为真的话？
3. 有序数组上的双指针，为什么在和太小的时候可以永久丢掉左端？
4. 二分的右端写成包含还是不包含，循环条件为什么要跟着变？
5. 同一套「边界测试」怎样用到一段数据处理代码上？

## 先把题写成三行

拿到一个问题，先写这三行再写代码：

- 输入：数据的形状、是否有序、元素范围。
- 输出：要返回的对象。有多个合法答案时，写明「任意一个」还是「全部」。
- 约束：`n` 最大是多少，时间上限大概是多少。

例：升序数组，返回任意一对下标 `i < j`，使 `nums[i] + nums[j]` 等于目标；不存在则返回空。`n` 可以到 `10⁵`，因此 `O(n²)` 的双重循环在这个约束下不合适，`O(n)` 合适。

大 O 写的是规模变大时的上界语言。它不代替计时。`O(n)` 的 Python 和 `O(n)` 的紧凑数值循环，常数可以差一个数量级。先用大 O 排除明显不够的算法，再对剩下的实现计时。

## 大 O 在说什么

只保留规模 `n` 增长时占主导的那一项。`3n + 20` 写成 `O(n)`，`n² + 100n` 写成 `O(n²)`。常用阶：`O(1)`、`O(log n)`、`O(n)`、`O(n log n)`、`O(n²)`。

同时说时间和额外空间。原地交换的双指针是 `O(n)` 时间、`O(1)` 额外空间。把数组复制到另一个结构里，额外空间就不再是 `O(1)`。

最好情况要单独声明分布。没有概率假设时，用最坏情况做约束判断。摊还是另一件事：动态数组偶尔一次扩容是 `O(n)`，分摊到前面每一次追加上可以是 `O(1)`。没有做摊还分析时，不把偶尔的贵操作叫 `O(1)`。

哈希表的一次查找，面试里说平均 `O(1)`。冲突严重时可以退化。这个差别在哈希那一篇展开，这里先记住「平均」两个字是有条件的。

下面三段的阶：

```python
def linear(n: int) -> int:
    total = 0
    for i in range(n):
        total += i
    return total  # 时间 O(n)，额外空间 O(1)


def quadratic(n: int) -> int:
    total = 0
    for i in range(n):
        for j in range(n):
            total += 1
    return total  # 时间 O(n²)


def halving(n: int) -> int:
    steps = 0
    while n > 1:
        n //= 2
        steps += 1
    return steps  # 时间 O(log n)
```

## 不变量

不变量是一句关于循环变量的话。循环开始前它为真，循环体每执行一次它仍为真，结束时它能推出你要的答案。

用它审查代码，比盯着下标是否加一更不容易漏掉边界。训练代码里的「标签比输入超前一位」就是一条不变量：每个被计损失的位置，预测的都是下一个 token。系统开篇会把它写成测试。

## 有序两数之和

输入数组升序。返回任意一对 `i < j`，或 `None`。

```python
def two_sum_sorted(nums: list[int], target: int) -> tuple[int, int] | None:
    """返回任意 i < j，使 nums[i] + nums[j] == target。不存在则返回 None。"""
    left, right = 0, len(nums) - 1
    while left < right:
        total = nums[left] + nums[right]
        if total == target:
            return left, right
        if total < target:
            left += 1
        else:
            right -= 1
    return None
```

不变量：若仍存在和为 `target` 的一对下标，则存在一对落在闭区间 `[left, right]` 内。

初始化时区间是整段数组，命题为真。若 `nums[left] + nums[right] < target`，那么 `left` 配上 `[left + 1, right]` 里的任何位置，和都不会更大，因为数组升序，那些值都不超过 `nums[right]`。所以 `left` 不在任何仍可行的解里，把 `left` 加一之后，不变量仍在。和太大时对 `right` 对称。`left >= right` 时区间里已经没有两个不同下标，返回 `None`。

因此每个下标最多被丢一次，时间 `O(n)`，额外空间 `O(1)`。

这条证明依赖升序。数组无序时，左端太小不能推出它和中间某个未检查元素也太小。无序的两数之和用哈希表，平均时间 `O(n)`，额外空间 `O(n)`。那是另一种不变量：已经看过的值都在表里。

Python 的整数不会在这个加法里溢出。把同一段代码搬到定宽整数时，要先规定和溢出怎么办。

参考实现和下面的用例由 `tools/check_worked_examples.py` 的 `check_algorithms` 复核。

| 输入 | 目标 | 返回 |
| --- | --- | --- |
| `[1, 2, 3, 4]` | 7 | `(2, 3)` |
| `[-3, -1, 0, 2, 4]` | 1 | `(0, 4)` |
| `[1, 1]` | 2 | `(0, 1)` |
| `[1, 2]` | 4 | `None` |
| `[1]` | 1 | `None` |

第二行里 `-1 + 2` 也等于 1。函数承诺的是任意一对，两端的 `-3 + 4` 会先被找到。测试若要求「字典序最小的一对」，这是另一个问题，现有证明不够。

## 二分的边界

在升序数组里找第一个大于等于 `target` 的下标。找不到时返回 `len(nums)`，这样返回值始终是插入位置。

```python
def lower_bound(nums: list[int], target: int) -> int:
    """第一个 >= target 的下标；不存在则返回 len(nums)。nums 升序。"""
    lo, hi = 0, len(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

这里 `hi` 是开区间的右端。不变量：答案在 `[lo, hi]` 里，`hi` 本身不包含。`nums[mid] < target` 时，`mid` 以及它左边都太小，新的 `lo = mid + 1`。否则 `mid` 仍可能是答案，`hi = mid`，`mid` 留在搜索范围内。`lo == hi` 时区间只剩一个候选，循环结束。因为右端开区间，`hi` 一开始可以是 `len(nums)`，用来表示「插在末尾」。

`[1, 3, 3, 5]` 上的结果：目标 0、1、3、4、5、6 分别对应下标 0、0、1、3、3、4。目标 3 必须返回第一个 3，也就是下标 1。

另一种写法把右端当成包含，循环条件就得写成 `lo <= hi`，更新时用 `hi = mid - 1`。两种都对，混用就错。下面这段把右端当成包含，循环却写成 `lo < hi`：

```python
def find_buggy(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

`nums = [1]`、`target = 1` 时，`lo == hi == 0`，循环不进入，返回 `-1`。`nums = [1, 3]`、`target = 3` 时，窗口收成 `lo == hi == 1` 后同样不再检查。把条件改成 `lo <= hi` 才和包含式右端一致：

```python
def find_fixed(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

Python 里 `(lo + hi) // 2` 不会溢出。用定宽整数时写成 `lo + (hi - lo) // 2`。

## 模式地图

代表题的名字用来自己找练习。题解不进这个仓库。

| 模式 | 何时考虑 | 不变量或核心动作 | 代表题关键词 | 容易写错 |
| --- | --- | --- | --- | --- |
| 双指针 | 有序数组上配对，或从两端收缩 | 解若存在，仍在当前窗口内 | 两数之和（有序）、验证回文 | 无序数组也从两端丢元素 |
| 滑动窗口 | 连续子数组，并且窗口能单调收缩 | 窗口始终满足约束 | 无重复字符的最长子串 | 收缩时忘记更新答案 |
| 前缀和 | 多次询问区间和 | `prefix[j] - prefix[i]` 等于区间 `(i, j]` | 区间和、和为 K 的子数组 | 忘记空前缀 0 |
| 二分 | 有序，或「可行性随答案单调」 | 可行区域是一段 | 查找左右边界、分割数组的最大值 | `lo`/`hi` 的开闭和循环条件不一致 |
| BFS | 无权图上的最短路、按层推进 | 第一次到达一个点时步数最少 | 迷宫最短路 | 入队之后才标记，导致重复入队 |
| DFS / 回溯 | 要枚举组合结构 | 路径上的选择可以撤销 | 子集、排列 | 递归返回前忘记撤销 |
| 堆 | 反复取当前最小或最大 | 堆顶是极值 | 前 K 个、合并 K 路有序 | 没比较「全排序」和「只维护 K 个」的复杂度 |
| 并查集 | 动态合并集合、查询是否连通 | `find` 返回代表元 | 连通分量个数 | 只写了合并、路径压缩不完整时结果仍可能对，但复杂度变了 |
| 动态规划 | 最优子结构，且子问题会重复 | `dp[状态]` 的定义能用一句话说完 | 背包、最长递增子序列 | 先写循环，后补定义 |
| 最短路 | 边权非负用 Dijkstra；有负权且无负环才用 Bellman-Ford | 距离只在松弛成功时下降 | 网络延迟 | 有负权仍用 Dijkstra |
| 拓扑排序 | 依赖关系，图应是 DAG | 入度为 0 的点才能作为下一步 | 课程表 | 有环时没有明确的失败结果 |

动态规划的顺序放在后面：先能把「状态表示哪一个子问题」写成一句话，再写转移。转移写出来而定义说不清的时候，边界几乎一定会错。

## 同一习惯用在数据流上

要统计一个 token id 流里有多少个不同的 id。

- 要精确集合：用哈希集合，期望时间 `O(n)`，空间 `O(不同 id 的个数)`。空间必须能装下这些 id。
- 只要基数的近似、不需要把 id 本身存下来：用 HyperLogLog 这类概率算法。它估计的是个数，恢复不出原来的集合。

先写输出是「精确集合」「精确个数」还是「近似个数」，再选结构。这一步和做题时先写输出是同一种动作。

## 容易算错的地方

- 约束是 `n = 10⁵` 时，嵌套两层 `n` 的循环不是「先写对再优化」的起点，它过不了约束。
- 双指针证明用了有序。把同一段代码用在无序数组上，丢掉的端点可能属于另一组解。
- `lower_bound` 的右端是开的，`find_fixed` 的右端是闭的。从一篇笔记复制循环时，连同开闭约定一起复制。
- 任意一对和全部对是两个规格。测试名字写上规格，避免以后把实现改成另一种却仍让旧测试绿色通过。

## 练习

### 练习 1：读循环的阶

- 目标：时间、额外空间一起说。
- 限制：不运行代码。
- 题面：给出正文 `linear`、`quadratic`、`halving` 的时间和额外空间。再看下面这段，`n` 是 `nums` 的长度：

```python
def copy_twice(nums: list[int]) -> list[int]:
    out = []
    for value in nums:
        out.append(value)
        out.append(value)
    return out
```

- 完成标准：四段都写出时间和额外空间。

<details>
<summary>参考解答</summary>

`linear`：时间 `O(n)`，额外空间 `O(1)`。`quadratic`：时间 `O(n²)`，额外空间 `O(1)`。`halving`：时间 `O(log n)`，额外空间 `O(1)`。`copy_twice`：时间 `O(n)`，额外空间 `O(n)`，因为输出长度是 `2n`。

</details>

### 练习 2：给两数之和补测试

- 目标：从规格写出失败用例，而不是只测快乐路径。
- 限制：先写用例，再对照脚本。可以运行 `python3 tools/check_worked_examples.py`。
- 题面：为 `two_sum_sorted` 写至少 5 个测试，覆盖空数组、单元素、无解、重复元素、负数。
- 完成标准：每个测试的期望值能由「任意一对」这个规格推出。存在多解时，期望值是这一实现会返回的那一对，并在注释里承认还有别的合法对。

<details>
<summary>参考解答</summary>

脚本中的五组是：`([1, 2, 3, 4], 7) → (2, 3)`，`([-3, -1, 0, 2, 4], 1) → (0, 4)`，`([1, 1], 2) → (0, 1)`，`([1, 2], 4) → None`，`([1], 1) → None`。空数组同样返回 `None`。第二组若期望 `(1, 3)`，那是另一对合法解，不是这个实现的返回值。

</details>

### 练习 3：改规格而不是改感觉

- 目标：看出不变量依赖规格。
- 限制：文字，不要求写出完整新代码。
- 题面：若规格改成「返回所有和为 target 的下标对，且每个值对只出现一次」，正文的哪一句不变量不再够用？指针移动会遇到什么新问题？
- 提示：考虑 `[-2, 0, 0, 2, 2]`、目标 0。
- 完成标准：指出至少两个新问题：多解要继续扫描；相等元素会造成重复对。

<details>
<summary>参考解答</summary>

原来的不变量只保证「还有解就在窗口里」，找到一对就返回。全部对需要在找到之后继续收缩，并且规定左右重复值怎样跳过。`[-2, 0, 0, 2, 2]` 里，`(-2, 2)` 会因为两个 2 产生重复下标对，`(0, 0)` 需要两个不同的 0。这些都要写进新的输出规格。

</details>

### 练习 4：修复二分

- 目标：让开闭约定和循环条件一致。
- 限制：先用 `find_buggy([1], 1)` 和 `find_buggy([1, 3], 3)` 预测返回值，再看代码。
- 题面：解释这两个调用为什么返回 `-1`。给出修复，并说明你改的是循环条件还是右端的含义。
- 完成标准：修复后的函数在这两个输入上返回正确下标，并且你能指出另一种合法写法是改成开区间，而不是唯一答案只有 `lo <= hi`。

<details>
<summary>参考解答</summary>

右端 `hi` 是包含的，但 `lo < hi` 在 `lo == hi` 时不再检查这个唯一剩下的下标。`[1]` 一开始就 `lo == hi`。`[1, 3]` 找 3 时，窗口会收成只剩下标 1。把循环改成 `lo <= hi` 即正文的 `find_fixed`。另一种合法修复是改成 `lower_bound` 那种半开区间，而不是保留现在的 `hi` 初始值。

</details>

### 练习 5：流式 token 的空间

- 目标：先写输出，再选数据结构。
- 限制：文字。
- 题面：一个长流里都是 token id。分别考虑三种需求：保存全部不同的 id、精确个数、允许误差的个数。每种需求的空间取决于什么？
- 完成标准：第三种提到近似算法估计的是基数，恢复不出 id 集合。

<details>
<summary>参考解答</summary>

精确集合的空间随不同 id 的个数增长，哈希集合是标准选择。精确个数如果不能接受误差，最坏情况下仍要记住见过的 id，否则无法区分「新 id」和「已经见过」。允许误差时可以用 HyperLogLog 一类算法估计基数，空间可以不随基数线性增长，但不能据此列回那些 id。

</details>

### 练习 6：把不变量写成一句话

- 目标：对 `lower_bound` 复述不变量。
- 限制：合上笔记。
- 题面：用一句话写出 `lower_bound` 循环里 `lo` 和 `hi` 的含义，并说明 `hi` 能不能作为下标去访问数组。
- 完成标准：提到 `hi` 可以等于 `len(nums)`。

<details>
<summary>参考解答</summary>

答案始终在半开区间 `[lo, hi)` 里。`hi` 可以是 `len(nums)`，这个值不是合法下标，不能访问 `nums[hi]`。

</details>
