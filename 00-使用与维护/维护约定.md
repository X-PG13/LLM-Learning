# 维护约定

这个仓库按增量更新。一次合并做完一件可以阅读的事：一篇笔记、一组练习的修订，或一次链接核对。

## 加一篇笔记

1. 从 [`笔记模板`](笔记模板.md) 复制结构。练习用 [`练习模板`](练习模板.md)。
2. 文件放进对应阶段目录，序号两位，例如 `02-概率.md`。不给还没写的主题建占位文件。
3. 记号服从 [`记号约定`](记号约定.md)。
4. 更新该阶段 `README.md` 的状态和链接。
5. 更新 [`01-路线图`](../01-路线图/README.md) 里同一行的状态和链接。两处行序保持一致。
6. 新的外部链接登记到 [`阅读清单`](../08-研究习惯/阅读清单.md)，写明用途。正文里的链接与清单保持同一地址。
7. 若改了手算数字或参考实现，同步 `tools/check_worked_examples.py` 并运行：

```bash
python3 tools/check_worked_examples.py
```

8. 根目录 `README.md` 只在阶段变化、入口笔记变化或使用方式变化时修改。不要把每一篇的细节复制进去。

## 怎样对待链接

阅读清单顶部记录最近核对日期。核对时打开页面，确认它仍然是原来的论文、文档或课程，而不是跳进网站首页。

失效时替换成同一作品的官方地址，或在该条目标明失效日期和原因。不要留着一个已经 404 的地址假装材料还在。

长时间中断后重新开始时，先抽查清单里标为「先读」的链接，再写新章节。

## 怎样对待路线图

路线图可以改。改的时候写明：是理解加深后的重排，还是某个主题已经有了笔记。已经写过的笔记若被移到别的阶段，留下原路径上的一个短文件指向新路径，避免自己的旧书签失效。第一版还没有这样的迁移。

新模型、新基准、新论文很多。只有当它改变了「算法工程师必须会判断的事」时，才加进路线图。其余的记到学习日志里，等下一次整理再决定。

## 提交

- 一个主题一次提交，写清楚改了哪一阶段。
- 不提交 `__pycache__`、虚拟环境和从网上下载的论文 PDF。
- 不把教材章节、讲稿或付费论文贴进仓库。引用用链接，解释用自己的话。
